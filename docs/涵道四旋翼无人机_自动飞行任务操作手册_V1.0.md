# 涵道四旋翼无人机自动飞行任务操作手册

文档版本：V1.0；更新日期：2026-09-12。运行工作空间：`/home/nrc/catkin_ws`。

## 本次任务

从地面静止位置记录 PX4 局部高度 `z₀`，起飞到 `z₀ + 1.0 m`，沿准备时的机头方向前飞 3.0 m，悬停 5 s，然后由 PX4 原生 AUTO.LAND 完成下降、落地判定和自动锁定。

前飞速度上限 0.3 m/s。降落速度使用飞控的 `MPC_LAND_SPEED`，最近只读值约 0.7 m/s；`COM_DISARM_LAND` 最近读值为 2 s。本次没有修改飞控参数，**该流程不承诺 0.2 m/s 缓降**。

一米是 PX4 测出的相对起飞点上升量。机体水平接地时中心约离地 0.1 m，上升一米后中心约离地 1.1 m。本次不要求连续有效的 `h_agl`，仍要求定位、实时点云、EGO 障碍检查和遥控器有效。起降区域保持平整、空旷；该模式不按地形变化自动保持离地高度。

本次仅进行了软件及隔离 ROS 验证，没有执行实机起飞或降落。操作员全程保持可接管遥控器。

## 终端 1：基础系统

~~~bash
cd /home/nrc/catkin_ws
source devel/setup.bash
roslaunch ducted_bringup base_system.launch
~~~

外部里程计转发已包含在基础系统中，不需要单独再启动。

## 终端 2：重定位

使用已经保存并匹配现场的地图；下面以 `site_a` 为例：

~~~bash
cd /home/nrc/catkin_ws
source devel/setup.bash
roslaunch ducted_bringup relocalization.launch \
  map_file:=/home/nrc/catkin_ws/maps/site_a/GlobalMap.pcd
~~~

程序自动搜索初始位置，成功后持续跟踪；也可在 RViz 的 `map` 坐标系使用 2D Pose Estimate 手动给初始位姿。等待地图及外部里程计就绪。

## 终端 3：检查、准备并加载任务

飞机放在平整地面，保持未解锁、静止，机头朝向计划前飞的方向：

~~~bash
cd /home/nrc/catkin_ws
source devel/setup.bash
rostopic echo -n 1 /ducted/localization/map_ready
rostopic echo -n 1 /ducted/external_odometry/ready
rostopic echo -n 1 /mavros/state
rostopic echo -n 1 /mavros/local_position/pose
~~~

两个 ready 应为 true，MAVROS 应 connected=true、armed=false，位置为新鲜有效的 odom 数据。然后执行：

~~~bash
python3 prepare_forward_test.py --confirm-flat-ground && bash launch_forward_test.sh
~~~

脚本生成本次起飞参考、航点和导航配置，并加载自动任务节点。它显式设置 `height_mode:=takeoff_relative`、`takeoff_rise:=1.0`、`finish:=land`。看到配置中的 `landing_mode: AUTO.LAND` 即表示采用原生降落。

这一条命令仅准备和加载，尚未开始飞行。不要重复启动独立的飞控、导航或航点节点。新模式不需要额外启动 terrain_height；若启动了，它仍只发布真实测高状态。

准备有效期 300 秒，单次使用。准备后移动飞机、改变机头方向、重启定位或更换 ROS 主节点，都应在未解锁状态停止本次任务节点并重新准备。不要直接复用旧 `launch_forward_test.sh`。

## 终端 4：检查并明确启动

~~~bash
cd /home/nrc/catkin_ws
source devel/setup.bash
rostopic echo -n 1 /ducted/rc/state
rostopic echo -n 1 /ducted/automatic/status
~~~

RC 应为 valid=true、mode=command、kill_switch=false；自动状态应为 IDLE、healthy=true、height_mode=takeoff_relative、finish=land。确认任务方向和周围空间后，由操作员使用遥控器解锁。保持飞机静止，在同一终端执行：

~~~bash
python3 prepare_forward_test.py --start
~~~

**这一步才真正启动自动飞行。** 程序再次检查准备文件、数据时效、控制开关、接地状态和飞控位置一致性。任何检查失败都会返回具体原因，不会自动重试飞行动作。

查看进度：

~~~bash
rostopic echo /ducted/automatic/status
~~~

正常顺序为接管 OFFBOARD、起飞、前飞、末点悬停、请求原生降落、等待落地及锁定，然后 SUCCEEDED。程序不会主动解锁，也不会因节点启动、重启或任务完成而自行再飞一次。

## 降落时会做什么

1. 航点到达并悬停五秒后，协调器调用 `/ducted/control/command` 的 `land`。
2. 飞控执行器通过 `/mavros/set_mode` 请求 `AUTO.LAND`。确认模式后，停止发送 OFFBOARD 位置目标。
3. PX4 按自身参数控制下降，判断接地并按配置自动锁定电机。
4. 上位机收到新鲜 ON_GROUND、armed=false 和控制器退出反馈，才将任务标记为成功。

不发送任意大的负 Z；不根据上位机看到“高度五秒不变”关闭电机；不要求落地时局部 Z 必须等于准备时 Z。降落速度和触地效果应依据实机日志观察，首次测试保留人工接管。

自定义 `slow_land` 和 `finish:=slow_land` 仍被拒绝，因为它们与当前固件的原生接地判定存在兼容问题。这个限制不影响本手册的 `finish:=land` 流程。

## 取消与再次执行

任务尚在 OFFBOARD 阶段、定位与控制有效时，可以在另一终端取消并请求保持：

~~~bash
rosservice call /ducted/automatic/cancel "{}"
~~~

已进入 PX4 原生降落后，取消上位机任务不会反向切回 OFFBOARD；需要改变飞行方式时由操作员通过遥控器接管。`Ctrl+C` 只是关闭节点，不能当作降落命令。

确认 landed_state=1、armed=false 后，再结束任务进程。重新执行必须在未解锁、静止状态重新准备；本次参考不可复用。

## 常见提示

| 提示 | 处理 |
|---|---|
| `old landing profile` | 当前准备文件来自旧流程；未解锁后重新准备，生成 finish=land 的文件 |
| `Slow landing is blocked` | 启动了旧的自定义缓降配置；停止旧任务节点，按本手册重新准备 |
| `automatic stack/profile not ready` | 查看状态 reason、height_mode、finish 和参考 Z 是否一致 |
| `PX4/external pose mismatch` | 检查外部里程计融合、坐标系和时间戳；暂不启动 |
| `PX4 takeoff datum consumed` | 本次准备已用过，重新准备 |
| `preparation expired` / `aircraft moved` | 保持未解锁并重新准备，随后在五分钟内完成检查和明确启动 |
| RC 无效或未授权 | 检查遥控器模式、急停及通道状态 |
| 起飞通道被阻挡 | 清空飞机上方和周围通道，检查实时点云 |
| AUTO.LAND 请求失败或超时 | 查看 MAVROS 和飞控状态，由操作员接管；程序不重复发送飞行动作 |

## 与上一版的区别

解除相对高度任务的临时启动拦截，任务收尾由自定义 0.2 m/s 下降改为 PX4 原生 AUTO.LAND。降落阶段去掉上位机五秒高度平台条件，以原生落地和锁定反馈完成任务。沿用 PX4 起飞点加一米、前飞三米、悬停五秒、EGO 实时避障和人工明确启动。

隔离测试结果位于 `logs/px4_relative_native_land/result.json`，验证 ROS 顺序和失败处理，不代表实机触地冲击或所有环境下的降落效果。
