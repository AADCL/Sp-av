# 涵道四旋翼无人机自动飞行任务操作手册

更新日期：2026-09-15。工作空间：`/home/nrc/catkin_ws`。控制器：C++ `ducted_offboard`；任务状态机与飞控执行器分离，在同一节点内各以 20 Hz 运行。

本手册主流程为：**使用所选地图重定位 → 启动控制器 → 输入前方 3 米任务点 → 人工下令起飞 → 悬停待命 → 人工下令执行 → 限速前进 → 到点悬停 → 人工下令降落 → 确认落地锁定**。

起飞默认相对本轮起飞点上升 1 米，不是实测离地高度，无需启动 `terrain_height.launch`。**EGO 源码保留但禁止运行，当前任务执行没有自动避障。** 起飞、直接航点跟踪和悬停由执行器负责，降落使用 PX4 `AUTO.LAND`。操作员需确认整段直达路径及降落区域可飞。

当前命令约定如下。各命令按操作阶段单独执行，不要一次连续发送：

| `/ctrl_cmd/state` | 操作 |
|---|---|
| `0` | 地面等待；空中暂停悬停 |
| `1` | 接管、解锁、起飞，完成后悬停等待 |
| `2` | 开始已加载任务，或恢复暂停任务 |
| `3` | 中断任务并请求 PX4 降落 |

本版需要更新后的控制器。已经运行的旧控制进程应在飞机落地锁定后关闭并重新启动，基础系统和重定位可继续运行。

## 一、终端分工与环境

以下命令均在远程主机 `nrc@192.168.50.140` 执行。该用户的新 Bash 终端已自动加载 ROS 和 `catkin_ws`，日常使用无需再输入 `source`。

| 终端 | 用途 | 保持运行到何时 |
|---|---|---|
| 一 | 基础系统、MAVROS、雷达、外部里程计转发 | 全部任务结束、其他功能关闭后 |
| 二 | 使用所选地图重定位 | 飞机落地锁定、控制器关闭后 |
| 三 | OFFBOARD 控制器（任务线程＋执行线程） | 飞机落地锁定后 |
| 四 | 检查状态、输入目标、下达指令 | 按步骤使用 |
| 五（可选） | 录包；RViz 可另开终端 | 录包在落地锁定后关闭 |

已有终端运行对应节点时不要重复启动。主流程使用单点话题任务；若需要文件、参数或多点话题，先阅读第十一节，在第三步选择对应入口。

## 二、第一步：启动基础系统

终端一执行，并保持运行：

```bash
roslaunch ducted_bringup base_system.launch
```

终端四检查：

```bash
rostopic echo -n 3 /ducted/system/ready
```

连续看到 `data: True` 后再启动定位。若为 `False` 或没有输出，先处理终端一中的设备报错。`-n 3` 会在收到三条消息后退出；没有消息时可按 `Ctrl+C` 结束检查。

基础系统已包含外部里程计转换和转发，无需另外启动。基础系统就绪不代表已经完成重定位。

## 三、第二步：选择地图并等待重定位成功

终端二设置本次使用的地图路径。以下默认示例为当前 `flight_test_01` 地图；使用其他场地地图时，修改第一行引号内的完整路径，再一起执行这三条命令：

```bash
MAP_FILE="/home/nrc/catkin_ws/maps/flight_test_01/GlobalMap.pcd"
ls -lh "$MAP_FILE"
roslaunch ducted_bringup relocalization.launch map_file:="$MAP_FILE"
```

`MAP_FILE` 是当前终端的地图选择变量，可改成任意与当前场地对应的有效 PCD 地图路径；控制器没有绑定 `flight_test_01`。若文件检查失败，先改正路径，再启动。不要省略 `map_file`：省略后 launch 会读取 `/home/nrc/catkin_ws/maps/GlobalMap.pcd`。本步骤不再同时启动 `mapping.launch`；没有已有地图时使用第十节的建图定位。

默认自动搜索初始位置。飞机保持未解锁，等待终端出现 `success=true` 和位姿结果。随后在终端四检查：

```bash
rostopic echo -n 1 /ducted/relocalization/status
rostopic echo -n 3 /ducted/relocalization/ready
rostopic echo -n 3 /ducted/localization/map_ready
rostopic echo -n 3 /ducted/external_odometry/ready
```

继续前应满足：重定位状态为 `TRACKING`、`success` 为 `true`，三个 ready 话题连续为 `True`。仅有本地位姿消息不能代替重定位成功判定。

**重定位成功后终端二必须一直运行。** 它继续提供局部定位和地图跟踪，不是返回坐标后就能关闭。

若自动初始化失败，可在未解锁时另开终端运行：

```bash
rviz
```

Fixed Frame 设为 `map`，添加 `/ducted/relocalization/global_map` 和 `/ducted/relocalization/registered_scan` 的 PointCloud2。将 Tool Properties 中 **2D Pose Estimate** 的 Topic 改为 `/ducted/relocalization/initialpose`，在地图中指定位置和机头方向，再检查上述状态。2D 工具默认 Z 为 0；若地图中的机体中心高度不同，需提供正确的完整初始位姿，详见[使用文档](涵道四旋翼无人机_使用文档_V1.0.md)。

## 四、第三步：启动直接跟踪控制器

飞机在地面且未解锁时，在终端三执行并保持运行：

```bash
rosparam set /ctrl_cmd/state 0
roslaunch ducted_offboard offboard_control.launch \
  target_source:=topic topic_mode:=single takeoff_height:=1.0
```

只启动一个控制器；不要运行旧控制进程。`ego_offboard.launch`、`ego_planner.launch`、`local_avoidance.launch` 和组合中的 `start_avoidance:=true` 已冻结，调用会报告“EGO 已冻结”，不会启动规划或控制节点。直接运行 EGO／导航节点同样拒绝；控制器传入 `execution_mode:=ego` 会失败，不会静默切换模式。

终端四检查：

```bash
rostopic echo -n 1 /ctrl_cmd/status
```

继续条件：`phase: IDLE_GROUND`、`command: 0`、`execution_mode: direct`、`connected: True`、`armed: False`、`landed_state: 1`、`input_ready: True`、`setpoint_active: True`。若为 `BOOT_WAIT_ZERO`，设置 `state 0` 并等待状态变化。

`planner_state: FROZEN`、`planner_ready: False`、空规划编号、`planner_target_age: -1` 都是当前版本的固定正常值。地面 `reference_valid: False` 正常，本轮起飞参考由执行器接管时确认。无需点云规划许可或实测 `h_agl`，但必须保持有效定位输入。

## 五、第四步：加载“前方 3 米、高度 1 米”任务

终端四发布一次最终任务点：

```bash
rostopic pub -1 /ctrl_cmd/target geometry_msgs/PoseStamped \
  "{header: {stamp: now, frame_id: mission_start}, pose: {position: {x: 3.0, y: 0.0, z: 1.0}, orientation: {w: 1.0}}}"
rostopic echo -n 1 /ctrl_cmd/status
```

确认终端三出现 `single target accepted`，状态中 `mission_loaded: True`、`waypoint_count: 1`，且仍为 `IDLE_GROUND`。

`mission_start` 在本轮接管时锁定：原点是起飞位置，X 指向当时机头前方，Y 向左，Z 向上。示例表示最终到达起飞点前方 3 米、上方 1 米，保持起飞航向；执行器直接向此点限速推进，不会绕障。目标接收一次后持续有效，不需要循环发布。

如需保留完整测试数据，在起飞前用终端五启动录包并保持运行：

```bash
roslaunch ducted_bringup recording.launch
```

## 六、第五步：人工下令起飞，然后悬停待命

确认定位持续有效、任务已加载、机体上方及预计飞行区域可飞，操作员持遥控器并能够接管后，在终端四执行：

```bash
rosparam set /ctrl_cmd/state 1
```

**这条命令会请求 OFFBOARD、解锁并起飞。** 无需手动调用解锁服务，节点不会绕过 PX4 的解锁检查。控制器已在地面预发送当前位姿，满足至少 2 秒预发送及输入条件后开始接管。

正常阶段顺序如下，以 `/ctrl_cmd/status` 的 `phase` 为准：

```text
IDLE_GROUND → OFFBOARD_REQUEST → ARMING → TAKEOFF → HOLDING
```

终端四持续观察：

```bash
rostopic echo /ctrl_cmd/status
```

起飞完成后进入 `HOLDING`，原因为 `takeoff complete; waiting for state=2`。此时只保持当前位置，**即使任务已加载，也不会自动前进**。规划字段持续显示冻结状态，不作为开始任务的条件。

`state=1` 只负责接管、解锁和起飞。等待起飞完成后再进入第六步；在 `TAKEOFF` 期间提前发送 `2` 会被拒绝，不会被排队执行。误操作后应等待悬停，先设置 `0` 并确认，再设置 `2`。

## 七、第六步：人工下令执行任务

确认 `phase: HOLDING`、起飞高度与姿态正常、任务已加载，并决定开始前进后，在终端四按 `Ctrl+C` 结束状态查看，执行：

```bash
rosparam set /ctrl_cmd/state 2
```

任务状态机将当前航点转换为 `odom` 并发给执行器，进入 `GUIDING`。执行器按水平 0.3 m/s、垂直 0.2 m/s、航向 20°/s 限制期望点变化；这些是目标推进上限，实际运动由 PX4 控制。终端四继续观察：

```bash
rostopic echo /ctrl_cmd/status
```

正常顺序为 `HOLDING → GUIDING → HOLDING`。最后一次 `HOLDING` 的原因应是 `mission complete; waiting for state=3`，表示任务完成，继续悬停等待第七步降落。

到点判断使用最终任务目标：水平误差 ≤0.15 m、高度误差 ≤0.10 m、航向误差 ≤10°、速度 ≤0.15 m/s，连续满足 1 秒，才判定到达。

`command` 只是最后一次外部命令，实际阶段看 `phase`。起飞后 `command: 1` 与 `HOLDING` 可同时出现；执行后 `command: 2` 与 `GUIDING` 或任务完成的 `HOLDING` 可同时出现。任务点序号不变也不能单独证明已经到点。

如进入 `PAUSED`，按第九节处理；进入 `ERROR` 或人工已切出 OFFBOARD，按第十二节处理。正在 `GUIDING` 时不需要重复设置 `2`。飞行中不要关闭终端一、二、三。

## 八、第七步：人工下令降落，确认锁定

到点悬停后，操作员确认降落区域，在终端四先按 `Ctrl+C` 结束状态查看，再执行：

```bash
rosparam set /ctrl_cmd/state 3
```

这里的 `Ctrl+C` 只结束终端四的 `rostopic echo`，不是关闭终端三的控制器。`3` 也可在任务尚未完成或暂停时请求降落，不必先设 `2`。

随后查看：

```bash
rostopic echo /ctrl_cmd/status
```

正常阶段为 `LAND_REQUEST → LANDING → IDLE_GROUND`，等待正常锁定时可能经过 `WAIT_DISARM`。确认飞控进入 `AUTO.LAND` 后停止 OFFBOARD 目标流。落地后等待 PX4 自动锁定；新鲜 `ON_GROUND` 状态持续 5 秒且仍解锁时，控制器请求正常锁定。

**落地完成以实际停桨且 `armed: False`、`phase: IDLE_GROUND` 为准。** 发出 `3` 或看到 `AUTO.LAND` 不代表已经完成。降落异常时不会强制锁定，也不通过“高度不变”判定停桨。

降落速度使用飞控当前 PX4 原生降落参数。直接跟踪的垂直目标推进速度 `0.2 m/s` 不等于 AUTO.LAND 的下降速度，本手册的启动命令没有修改 PX4 降落参数。

落地锁定后：

- **继续下一轮**：终端四设置 `rosparam set /ctrl_cmd/state 0`，按第四步重新发布单点任务并确认加载，再按第五步起飞；本轮起飞位置和航向重新锁定。
- **结束测试**：先关闭终端三，再关闭录包并等待保存完成，然后关闭终端二，最后关闭终端一。均使用各自终端的 `Ctrl+C` 正常退出。

## 九、飞行中的暂停与恢复

本节是人工暂停、任务超时或任务线程心跳中断时使用的分支，不是每次飞行都要依次执行的步骤。

需要暂停时，终端四执行：

```bash
rosparam set /ctrl_cmd/state 0
```

确认 `phase: PAUSED`。定位有效且仍在 OFFBOARD 时，任务层下发新悬停请求，执行器捕获当前位置悬停。`0` 不表示降落或停桨，不能替代遥控器应急接管。

排除问题并决定继续后，执行：

```bash
rosparam set /ctrl_cmd/state 2
```

`2` 用于空中暂停或悬停状态下启动／恢复任务。恢复会使用新的内部执行请求编号，从当前位置限速跟踪未完成的最终目标。若此前命令已是 `2`，先设置 `0` 并确认控制器观察到它，再设 `2`；连续写相同数值不会再次触发。

任务线程恢复或新任务到达不会自动解除 `PAUSED`。暂停期间的新序列替换待执行列表，恢复后从新序列首点开始；没有新序列则继续未完成的点。

已完成任务的 `HOLDING` 状态下，不要为了“确认完成”发 `2`：代码允许从悬停开始任务，可能重新执行已加载任务。正常结束直接发送 `3` 降落。

## 十、没有地图时改用建图定位

已有地图不是当前自动控制的必需条件。不加载地图时，只替换主流程第二步：

```bash
roslaunch ducted_bringup mapping.launch
```

此时不启动重定位，检查 `/ducted/system/ready`、`/ducted/localization/frames_ready` 和 `/ducted/external_odometry/ready` 持续有效，不要求 `map_ready` 或重定位 `TRACKING`。第三步控制器及后续任务命令完全相同，无需修改点云话题。

两种定位只选一种；切换前先落地锁定，关闭控制器和原定位入口，再按基础系统、定位、控制器顺序运行。

## 十一、文件、参数和多点话题任务

本节是在**第三步启动前**选择其他输入方式，不能在已运行单点控制器后再启动第二个控制器。更换输入方式需在地面未解锁时关闭原终端三，设置 `state 0` 后启动所选控制入口；终端一、二保持运行。

文件、参数和话题输入均由任务状态机管理，两种定位方式使用相同命令。

### 11.1 YAML 文件任务

终端三执行：

```bash
rosparam set /ctrl_cmd/state 0
roslaunch ducted_offboard offboard_control.launch \
  target_source:=file \
  mission_file:=/home/nrc/catkin_ws/src/ducted_offboard/config/mission_example.yaml
```

示例文件为：

```yaml
frame_id: mission_start
waypoints:
  - {x: 0.0, y: 0.0, z: 1.0, yaw_deg: 0.0}
  - {x: 3.0, y: 0.0, z: 1.0, yaw_deg: 0.0}
```

文件在节点启动时读取。终端四确认 `mission_loaded: True`、`waypoint_count: 2` 后，无需再执行第四步的单点发布，直接从第五步继续。

### 11.2 参数任务

终端三在启动前设置完整列表：

```bash
rosparam set /ctrl_cmd/state 0
rosparam set /ducted_offboard_controller/waypoints \
  '[{x: 3.0, y: 0.0, z: 1.0, yaw_deg: 0.0}]'
roslaunch ducted_offboard offboard_control.launch \
  target_source:=param
```

默认参数任务坐标为 `mission_start`。列表在启动时读取，运行后仅修改参数不会自动更新任务。终端四确认加载成功后，从第五步继续。

### 11.3 多点话题任务

终端三执行：

```bash
rosparam set /ctrl_cmd/state 0
roslaunch ducted_offboard offboard_control.launch \
  target_source:=topic topic_mode:=sequence
```

终端四发布一次序列，替代第四步的单点发布：

```bash
rostopic pub -1 /ctrl_cmd/waypoints nav_msgs/Path \
  "{header: {stamp: now, frame_id: mission_start}, poses: [{pose: {position: {x: 2.0, y: 0.0, z: 1.0}, orientation: {w: 1.0}}}, {pose: {position: {x: 2.0, y: 1.0, z: 1.0}, orientation: {w: 1.0}}}]}"
rostopic echo -n 1 /ctrl_cmd/status
```

确认 `mission_loaded: True`、`waypoint_count: 2` 后，从第五步继续。每个最终任务点单独交给飞控执行器，到点并满足连续停留条件后才推进下一点。全部完成悬停后，仍需人工发送 `3` 降落。

序列落地后保留原始任务点，下轮按新起飞参考重新解析；地面也可重新发布替换。单点话题任务落地后清除，下轮需重发。单点模式在 `GUIDING` 中收到新目标时会替换当前执行目标；在 `HOLDING` 或 `PAUSED` 时只加载新目标，仍需显式 `2` 才执行。若当前命令已是 `2`，先设置 `0` 并确认，再设置 `2`。

### 11.4 显式 odom 坐标

文件和话题可将 `frame_id` 设为 `odom`；参数任务需在所选 `config_file` 文件中设置 `mission_frame: odom`。目标不再按起飞航向旋转，Z 是固定本地坐标高度，`z: 1.0` 不一定表示相对起飞点高 1 米。不要把地图 `map` 坐标直接标成 `odom` 发送。

## 十二、状态、故障与日志

以下命令各自持续输出，用独立终端，或按 `Ctrl+C` 结束查看再运行下一条：

```bash
rostopic echo /ctrl_cmd/status
```

```bash
rostopic hz /mavros/setpoint_position/local
```

位置目标在预发送、起飞、跟踪和悬停期间约为 20 Hz，确认 AUTO.LAND 后停止是预期行为。当前只有 `/ducted_offboard_controller` 发布该位置目标话题。

| 状态字段 | 如何使用 |
|---|---|
| `command` | 最后观察到的外部指令，不是实际飞行阶段 |
| `phase` / `reason` | 当前综合阶段及原因，用于主流程判断 |
| `task_phase` | 任务线程的阶段，如 GUIDING、HOLDING、PAUSED |
| `executor_phase` | 执行器实际阶段，包括 OFFBOARD_REQUEST、ARMING、TAKEOFF、LANDING |
| `task_generation` | 每轮接管递增的任务代次 |
| `task_heartbeat_age` | 内部任务快照距今秒数，正常约 0～0.1；超 0.5 s 撤销推进 |
| `reference_valid` / `takeoff_reference_z` | 执行器确认的本轮起飞参考，落地后撤销 |
| `planner_state` / `planner_ready` | 固定 FROZEN / False，当前没有规划许可 |

任务心跳超时后，地面不再请求接管或解锁；空中定位有效且仍在 OFFBOARD 时捕获当前位置悬停。任务线程恢复后仍保持暂停，需要操作员按第九节显式恢复。已经进入的降落流程由执行器继续完成。新请求会使未派发的旧服务请求失效；迟到服务响应不会推进新任务。

| 现象 | 处理 |
|---|---|
| `BOOT_WAIT_ZERO` | 先设置 `state=0` 并确认被观察到 |
| `mission_loaded: False` | 检查输入方式、目标话题、时间戳和任务格式；确认加载后才起飞 |
| OFFBOARD 重试或解锁拒绝 | 检查 MAVROS/PX4 提示、定位与飞控检查；最多 4 次请求 |
| `guiding command rejected outside an airborne hold` | 等待起飞完成；若已 GUIDING，无需重复发 2 |
| `task heartbeat expired` | 执行器已撤销推进；查任务线程/参数访问日志，恢复后先 0 再 2 |
| `waypoint timeout` / `takeoff timeout` | 定位有效时悬停；检查实际位置、目标、速度和超时原因 |
| `service call did not return` | 请求超时进入 ERROR；迟到响应不能解除错误，不反复触发接管 |
| 位姿、速度或飞控状态过期 | 停止旧目标输出；由操作员或 PX4 既有失效保护处置 |
| `left OFFBOARD` / `ERROR` | 自动输出已停止，不会抢回控制权；落地锁定并排除原因后重启控制器 |
| 落地仍解锁 | 检查新鲜 ON_GROUND、正常锁定请求和 PX4 提示，不用关闭节点替代停桨 |
| `EGO 已冻结` | 使用第三步的直接控制入口，当前不提供运行解冻参数 |

日志在 `/home/nrc/catkin_ws/logs/offboard_control/session_<UTC>_<PID>/`。事件中 `[Task]` 与 `[Executor]` 区分两层，记录命令、执行请求与确认、阶段、到点及服务反馈。CSV 默认 5 Hz，包含两层阶段和心跳年龄；`config.yaml` 保存实际配置。日志通过有界队列异步写盘并轮换，磁盘慢不会持有执行循环的锁，队列满会报告丢弃记录数。

```bash
latest_log=$(ls -td /home/nrc/catkin_ws/logs/offboard_control/session_* | head -n 1)
echo "$latest_log"
tail -n 80 "$latest_log/events.log"
```
