# 涵道四旋翼无人机自动飞行任务操作手册

文档版本：V1.0；更新日期：2026-09-12。

任务：从地面起飞至机体中心离地 1.0 m，沿准备时的机头方向前飞 3.0 m，悬停 5 s，再缓慢下降。前飞速度上限 0.3 m/s；下降位置目标按 0.2 m/s 变化，实测速度取决于 PX4 的跟踪效果。机体底部比中心低约 0.1 m。前飞阶段保持起飞后的绝对高度，地面变化时离地高度会变化。

代码保存在 `/home/nrc/catkin_ws`。所有命令在远程 Ubuntu 终端执行；每个 launch 保持运行。准备和启动是两个独立操作，脚本不解锁飞机。操作员确认飞行区域、遥控器接管功能后手动解锁。

使用五个终端：**基础系统 → 重定位 → 地面高度 → 准备并加载任务 → 检查与启动**。

本任务准备脚本要求 `map_ready=true`，任务组合使用重定位点云，所以必须使用当前场景的已建地图完成重定位。仅运行 `mapping.launch` 不满足本手册的任务条件；建图与重定位二选一。

## 终端 1：基础系统

```bash
cd ~/catkin_ws
source devel/setup.bash
roslaunch ducted_bringup base_system.launch
```

基础层已经包含外部里程计转发；定位就绪后自动向 PX4 发送，无需另开终端。不要重复启动 `external_odometry.launch`。若正在使用旧版基础层，应在飞机未解锁时关闭旧实例，再启动更新后的基础层。

## 终端 2：重定位

新终端，地图须与现场一致：

```bash
cd ~/catkin_ws
source devel/setup.bash
roslaunch ducted_bringup relocalization.launch \
  map_file:=/home/nrc/catkin_ws/maps/site_test_01/GlobalMap.pcd
```

启动后保持未解锁，程序默认自动搜索未知初始位置和姿态。首次定位成功后终端打印 `success=true`、机体中心的地图坐标和匹配质量，并继续运行地图跟踪；整个飞行任务期间都保持终端 2 运行。

自动初始化失败或希望指定起点时，在 RViz 中设置 Fixed Frame 为 `map`，显示 `/ducted/relocalization/global_map`，把 `2D Pose Estimate` 工具话题设置为 `/ducted/relocalization/initialpose`，标出实际位置和朝向。有效手动初值优先，会中断自动搜索；2D 工具默认 Z=0，必要时提供完整三维机体中心初值。不要放宽匹配阈值。

在检查终端查看 `/ducted/relocalization/status`，确认 `state=TRACKING`、`success=true`，且 `/ducted/localization/map_ready` 持续为 `true` 后再准备任务。`/ducted/relocalization/retry` 可在未解锁状态重新触发自动搜索，服务受理成功不代表已经匹配成功。起飞或执行任务期间不得重新指定初始位姿；程序会拒绝已解锁时的初始化请求。

## 终端 3：地面高度

```bash
cd ~/catkin_ws
source devel/setup.bash
roslaunch ducted_bringup terrain_height.launch reference_confirmed:=true
```

重定位流程使用默认话题 `/ducted/localization/odom` 和 `/ducted/localization/cloud_registered`。采用 `base_link` 中心参考。贴地时雷达可能无法识别地面，允许输出 `valid: false`；后面的明确接地确认用于初始化起飞参考，不会改变雷达测量的有效性。

高度节点已改为按点云时间戳匹配里程计缓存，支持消息先后到达，配对容差仍为 50 ms。若高度无效，按日志的具体原因处理；不要放宽容差来掩盖不同步。

## 终端 4：检查、准备并加载任务

飞机保持在地面、未解锁、静止，机头指向要前飞的方向：

```bash
cd ~/catkin_ws
source devel/setup.bash
rostopic echo -n 1 /ducted/localization/map_ready
rostopic echo -n 1 /ducted/external_odometry/ready
rostopic echo -n 1 /ducted/terrain/height
```

前两个话题应为 `data: true`。高度节点必须持续发布当前时间的 `odom` 消息，但贴地时可以 `valid: false`。确认飞机**底部实际接触平整地面、机体保持水平且静止**后执行下面的准备命令。桌面、支架和手持状态不能使用这个接地确认。

```bash
python3 prepare_forward_test.py --confirm-ground-contact && bash launch_forward_test.sh
```

`&&` 确保准备成功后才启动任务节点。脚本生成 `logs/forward_3m_<编号>/` 下的任务和配置，以及根目录 `launch_forward_test.sh`。确认生成的 `height_source` 为 `CONTACT_REFERENCE`。接地确认有效期为 300 秒，且每份参考只允许启动一次。准备后不要移动飞机或重启定位；否则保持未解锁，关闭本终端任务节点后重新准备。启动节点本身不会起飞，终端 4 保持运行。

本组合会启动遥控处理、飞控执行器、EGO、航点任务和自动协调节点。若有独立运行的相同功能节点，先在未解锁状态关闭独立实例，避免重复启动。

准备脚本会显示本次目标坐标，自动生成航点和规划配置。接地时中心离地约 0.10 m，因此目标中心离地 1.0 m 对应从初始绝对高度上升约 0.90 m。前飞方向取准备时的机头方向。

如果已有持续可靠的雷达高度，也可不传 `--confirm-ground-contact`，沿用实测高度准备；未明确确认接地时，程序不会自动假定飞机在地上。

## 终端 5：检查遥控器并启动

新终端先观察：

```bash
cd ~/catkin_ws
source devel/setup.bash
rostopic echo -n 1 /ducted/rc/state
rostopic echo -n 1 /ducted/automatic/status
rostopic echo -n 1 /mavros/state
```

必须看到遥控器 `valid: true`、`mode: command`、`kill_switch: false`，自动任务 `state: IDLE`、`healthy: true`。确认遥控器开关与这些状态对应；当前配置 CH5 为模式、CH7 为解锁、CH8 为 kill。飞控应为 `connected: true`，手动解锁前 `armed: false`；`healthy: false` 时查看 `health_reason`。条件满足后由操作员用遥控器解锁，再执行：

```bash
python3 prepare_forward_test.py --start
```

输出 `success: True` 表示启动请求被接受，随后程序申请 OFFBOARD 并执行任务。观察：

```bash
rostopic echo /ducted/automatic/status
```

`--start` 会再次核对位置、朝向、高度和就绪状态，再请求任务。启动失败时按错误原因处理，不要连续重试不明确的服务结果。正常完成状态为 `SUCCEEDED`，且收到落地及锁定反馈。

自动协调器状态通常经过 `ENGAGING / WAIT_OFFBOARD`、`WAIT_TAKEOFF`、`RUNNING`、`LANDING`，最后为 `SUCCEEDED`。缓降期间，`/ducted/control/status` 中执行器状态为 `SLOW_DESCENT`。

## 取消、落地与再次执行

需要取消时，在终端 5 按 `Ctrl+C` 停止状态显示，再执行以下命令。停止状态显示本身不会取消任务。

```bash
rosservice call /ducted/automatic/cancel "{}"
```

取消会停止任务并在有效定位与 OFFBOARD 控制下请求悬停，不等于关电机或降落。需要时通过遥控器接管；飞行中不要用关闭 launch 代替正常取消。定位失效、地面多层歧义或超出近地参考限制时停止缓降，不会自行恢复。只有下文限定的近地可见性不足允许使用短时落地参考。

落地后检查：

```bash
rostopic echo -n 1 /mavros/extended_state
rostopic echo -n 1 /mavros/state
```

确认 `landed_state: 1`（ON_GROUND）和 `armed: false`。再次飞行时，关闭终端 4 的任务组合，保持未解锁，重新准备并加载任务；定位仍有效时终端 1～3 可以继续运行。

## 高度来源与近地盲区

| 阶段 | 高度来源与要求 |
|---|---|
| 地面准备 | `CONTACT_REFERENCE`：操作员明确确认接地，使用机体尺寸和当前绝对定位建立地面参考；雷达消息仍可无效 |
| 垂直起飞 | 参考最多使用 8 秒（从接受任务开始），中心离地不超过 1.1 m、水平偏离准备点不超过 0.15 m；超限中止并请求保持 |
| 雷达接管 | 至少 3 个不同时间戳的有效测量，跨度至少 0.15 秒，并与起飞地面参考相差不超过 0.08 m；来源变为 `LIDAR`，失效后不退回起飞参考 |
| 前飞任务 | 必须取得有效实测 `h_agl` 后才启动；EGO 始终使用真实地面高度 |
| 缓降近地 | 来源可为 `LANDING_REFERENCE`；使用本次下降中稳定测得的落地区地面，不能复用起飞处地面 |

近地缓降参考只处理地面点数或支撑不足：机体中心离地至多 0.35 m，最后有效测量时至多 0.40 m，参考年龄至多 3 秒，水平偏离最后测量点至多 0.10 m。高度节点消息、定位和姿态必须继续更新；多层地面、地面突变、不同步、数据中断和倾斜超限仍停止下降。满足接地反馈后才请求 `AUTO.LAND`，不会仅凭估算高度强制锁定。

查看来源：自动任务状态中的 `height_source / height_measured`，以及飞控状态中的 `height_source / height_reference_valid`。雷达高度消息新增 `reason`，`valid: false` 和 `nan` 不会被初始化参考伪装成实测值。

升级后在未解锁状态重启旧的高度节点与任务组合，并重新准备；这次增加了 ROS 消息字段，旧进程不能继续混用。

## 常见提示

| 提示或现象 | 处理方式 |
|---|---|
| `map_ready` 为 false | 核对地图与初始位姿，完成重定位后再准备任务 |
| 外部里程计未就绪 | 检查更新后的基础层、定位数据及 `/ducted/localization/frames_ready`；不要重复启动转发节点 |
| `odometry unavailable or stale` | 检查重定位中的本地 FAST-LIO 是否持续发布 `/ducted/localization/odom` |
| `odometry and point cloud timestamps are skewed` | 重启更新后的高度节点；若持续出现，核对默认话题与发布者，排查重复定位实例或数据延迟 |
| `insufficient terrain support at reference` | 雷达实测高度无效；贴地可通过明确接地确认准备。离地后仍持续出现时不得进入前飞，检查点云覆盖和遮挡 |
| `valid synchronized center-AGL measurement required` | 实测准备路径要求有效高度；实际位于平整地面时，改用明确的接地确认参数重新准备 |
| `contact preparation expired` 或 `contact reference already consumed` | 未解锁状态关闭任务组合，重新准备，不能重用旧参考 |
| `takeoff ground-reference height/time/motion limit exceeded` | 在限定范围内没有完成雷达接管，前飞被阻止；处理测高问题后重新准备 |
| `ambiguous multi-level terrain` | 检测到多个候选地面，空中不能用近地参考绕过此错误 |
| `RC does not grant automatic authority` | 检查遥控器为 command 模式、急停未触发；当前 CH8 配置为急停 |
| `aircraft moved or localization changed since preparation` | 未解锁状态下关闭任务组合，重新准备 |
| `target outside the existing flight envelope` | 生成目标超出当前飞行范围，停止准备并核对坐标 |
| `takeoff corridor is not clear` | 起飞通道未通过检查，检查机体上方障碍及点云 |
| `ABORTED` 或 `FAULT` | 查看 `reason`；通过遥控器完成必要处置，落地锁定后重新初始化任务 |

## 配置变化与软件验证记录

基础层自动启动外部里程计转发，地面高度使用本地 FAST-LIO 的 `camera_init/body` 链，并按点云时间戳匹配里程计。`slow_land` 在缓降接地确认后交给 PX4 完成落地锁定，不直接强制锁定。

本任务配置将导航 `min_agl` 从 0.4 调为 0.3 m，使计入包围体和安全余量后的中心高度下限低于 1.0 m；机体外形和其他碰撞余量保留，默认导航配置文件不变。

本次近地修正通过 129 项针对性测试。独立 ROS 主节点上的完整模拟任务通过 23 项检查；起飞后始终测不到地面的场景通过 16 项检查，确认中止前飞并保持位置。结果见[近地起降软件验证记录](verification/2026-09-11-near-ground.md)。这些是软件模拟结果，没有执行实机起飞，也不代表实际点云已经能在所有高度识别地面。

历史检查曾出现地图匹配失败、地面支撑不足和急停触发；历史结果不代表本次状态，操作以当前话题和脚本检查为准。

本次自动全局重定位、手动初值和持续跟踪的验证结果见[2026-09-12 验证记录](verification/2026-09-12-global-relocalization.md)。
