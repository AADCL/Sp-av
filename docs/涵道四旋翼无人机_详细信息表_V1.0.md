# 涵道四旋翼无人机详细信息表

控制指令采用分步操作：`state=1` 只起飞并悬停，`state=2` 才开始／恢复任务，`state=3` 降落；悬停时收到新目标只加载，不自动执行。

2026-09-15：EGO 源码保留但运行冻结。当前 C++ `ducted_offboard` 将任务状态机和飞控执行器拆为独立模块与 20 Hz 线程，保持一个节点，仅支持直接限速航点跟踪，**没有自动避障**。1 起飞后悬停，2 执行／恢复任务，3 使用 PX4 AUTO.LAND 降落。

> 用于快速查询硬件、网络、机体几何、外参、节点、话题、启动文件、参数和已有验证结果。  
> 文档版本：V1.0；硬件配置核对日期：2026-09-12；软件与文档更新日期：2026-09-15。数值以本机 `/home/nrc/catkin_ws` 当前配置为依据。
> 日常操作见《使用文档》，源码组织与构建见《开发实施文档》。

## 3. 机体几何、外参与 TF

### 3.1 机体包络

采用FLU约定：X向前、Y向左、Z向上。单位为米。

| 轴 | 最小值 | 最大值 |
|---|---:|---:|
| X | -0.30 | +0.30 |
| Y | -0.35 | +0.35 |
| Z | -0.10 | +0.10 |

八个顶点统一保存在 `src/ducted_bringup/config/airframe_geometry.yaml`，由地面高度和局部避障启动文件共同加载。
避障算法采用包住该长方体的球体，半径约0.4717 m，再加入净空及运动余量；此半径是算法包络，不是机体实际半宽。

### 3.2 两类外参

| 配置关系 | 平移，m | 旋转 | 使用位置 |
|---|---|---|---|
| MID360内部雷达到内部IMU | `[-0.011, -0.02329, 0.04412]` | 单位矩阵 | 建图、重定位的 `mapping/extrinsic_T`、`extrinsic_R` |
| 内部IMU状态坐标系在 `base_link` 中的安装位姿 | `[0.13, 0, 0]` | RPY=`[0.03, 0.4567, 0]` rad | 里程计适配器的 `extrinsic/base_to_livox` |

安装角约为Roll 1.72°、Pitch 26.17°、Yaw 0°。配置复用本机原厂 `spirit-wing_v1.0` 的MID360启动文件；其中静态TF命令的角度顺序为yaw、pitch、roll，转换到YAML后采用roll、pitch、yaw。

`reused_unverified` 表示这份原厂安装配置没有在本轮独立测量精度，不表示来自其他机型。
FAST-LIO的 `body` 状态（原命名为`livox_frame`）位于MID360内部IMU原点；内部雷达—IMU外参不能再作为机体安装平移重复叠加。

### 3.3 TF发布关系

适配器有效工作时，定位主链为：

~~~text
odom → camera_init → body → base_link
~~~

| TF | 行为 | 发布者 |
|---|---|---|
| `odom → camera_init` | 初始化后固定旋转，随有效里程计时间戳发布 | `/localization_frames`（`fastlio_odometry_adapter.py`） |
| `camera_init → body` | FAST-LIO动态状态 | 建图`/mapping`；重定位`/ducted/local_lio/fastlio` |
| `body → base_link` | 安装关系的逆变换，作为静态TF发布 | `/localization_frames`（`fastlio_odometry_adapter.py`） |
| `odom → odom_ned` | ENU/NED坐标约定转换 | MAVROS内部话题（不进入公共TF树） |
| `base_link → base_link_frd` | FLU/FRD坐标约定转换 | MAVROS内部话题（不进入公共TF树） |

MAVROS的 `local_position/tf/send=false`，不再发布另一条 `odom → base_link` 动态边。
基础层单独运行时不会提供完整定位主链。建图或重定位自动启动 `/localization_frames`，在定位有效且未解锁飞控姿态可用后连接完整TF；外部发送门控关闭不影响TF。

## 4. 正式启动入口

除新控制入口属于 `ducted_offboard` 外，其他入口位于 `ducted_bringup`。先启动基础层，再按需启动其他功能。

| 功能 | 命令或入口 | 默认行为 |
|---|---|---|
| 基础层 | `roslaunch ducted_bringup base_system.launch` | MAVROS、Livox、健康监视、外部里程计转发 |
| 建图 | `roslaunch ducted_bringup mapping.launch` | 等待基础层；显式保存地图 |
| 重定位 | `roslaunch ducted_bringup relocalization.launch map_file:=/绝对路径/GlobalMap.pcd` | 加载指定 PCD，默认自动搜索未知位姿，成功后持续跟踪 |
| 外部里程计 | 基础层末尾包含 `external_odometry.launch` | 基础层传入确认参数true；等待有效定位后自动发送 |
| 相对地面高度 | `terrain_height.launch` | `reference_confirmed=false` |
| 遥控处理 | `rc_processing.launch` | `mapping_confirmed=false` |
| EGO 规划入口 | ego_planner / local_avoidance / ego_offboard | 已冻结，明确拒绝运行 |
| 直接控制 | `roslaunch ducted_offboard offboard_control.launch` | 任务与执行器分线程；无自动避障 |
| 数据记录 | `recording.launch` | 基础层连续就绪后建立记录 |
| 按需组合 | `modules.launch` | 所有功能开关默认关闭，不隐式启动基础层 |

建图与重定位不能同时运行。组合入口可按需启用一份RC监视。

| `/ctrl_cmd/status` | `ducted_offboard/OffboardStatus` | 10 Hz | 两层状态、任务代次与心跳年龄 |
| `/mavros/setpoint_position/local` | `geometry_msgs/PoseStamped` | odom、20 Hz | 唯一活动执行器输出 |

以上是机载电脑上的 ROS 接口。`/mavros/odometry/out` 将外部定位送入 PX4；位置目标由 `ducted_offboard` 通过 `/mavros/setpoint_position/local` 发送。MAVROS 经 `/dev/ttyTHS0`、921600 波特率传输 MAVLink 2。飞控状态、位置和落地反馈分别通过 `/mavros/state`、`/mavros/local_position/pose`、`/mavros/extended_state` 返回。

高度约定：定位保留固定坐标；原始 `map` 可能倾斜，由适配器建立竖直 `odom`。这里的绝对高度是本地固定坐标高度，不是海拔。
默认 `agl` 是机体中心到地面的竖直距离。水平姿态下机底离地高度为 `agl - 0.10 m`；倾斜时应按旋转后的包络最低点计算。

候选高度计算为 `candidate_agl = measured_agl + candidate_z - current_z`。
规划输出仍为绝对 `odom` 位置，不把地面起伏叠加到定位Z，也不自动改成恒定离地高度任务。

地图保存脚本：`/home/nrc/catkin_ws/save_map.sh`。在工作空间根目录执行 `./save_map.sh`，自动加载环境，以 `map_时间戳` 命名并保存到 `maps/`；`./save_map.sh site_c` 可指定新目录名。默认保存分辨率0.05 m，已有目录拒绝覆盖。

脚本显示后台进度，成功后打印 `GlobalMap.pcd` 完整路径。`./save_map.sh --status` 查询最新任务，`./save_map.sh --wait` 重新显示进度。Ctrl+C 只退出显示，后台保存继续；基础系统和建图必须保持运行，机体保持静止，直到 `SUCCEEDED` 或“保存完成”。

原 Python 入口 `rosrun ducted_bringup save_map.py start --destination /新地图目录` 继续提供完整路径和分辨率设置。任务文件位于 `logs/map-save-jobs/`；逐帧进度参数为 `/ducted/mapping/save_progress`。后台进程异常退出时标记 `UNKNOWN`，不自动重复提交。


本版按运行阶段划分公共TF（2026-09-12更新）：

- 仅基础系统：无定位TF边，不出现`map`、`odom`、`camera_init`或`body`定位链；`base_link`为机体参考。
- 建图：`odom → camera_init → body → base_link`，不存在`map`。
- 重定位成功且源数据新鲜：`map → odom → camera_init → body → base_link`。

`camera_init → body`由独立的局部FAST-LIO发布。默认 `ducted_localization` 复用该局部点云，以 FPFH/RANSAC 完成未知位姿初始化，随后约 1 Hz 做点到面 ICP 地图跟踪。它把有效全局校正应用到每条新鲜局部里程计，保留完全相同的源时间戳，发布 `/ducted/relocalization/global_odom`（map/body）且不发布 TF。`world_tf_owner.py`按相同扫描时间戳配对全局与局部机体位姿，计算`T_map_odom = T_map_base × inverse(T_odom_base)`；全局校正不会重置局部FAST-LIO。数据过期或重定位无效时停止发布全局校正，`/ducted/localization/map_ready=false`。TF缓存可能短暂保留旧变换，不应只看树中是否还显示map判断定位有效。

`body`是MID360内部IMU参考，不是机体中心；`body → base_link`为原安装外参的逆变换，外参数值未改。保存PCD坐标沿用建图的`camera_init`数值，加载后将该固定地图坐标命名为`map`，建图时无需发布map TF。重定位RViz的Fixed Frame使用`map`；建图使用`odom`或`camera_init`。

MAVROS的ENU/NED、FLU/FRD辅助变换移至`/mavros/internal_tf_static`，其内部里程计转换仍使用这些变换，公共TF树不再出现辅助根。旧`odom → map`链已移除。默认重定位使用一个局部 FAST-LIO 和一个独立配准工作进程；不会同时启动旧 `sfast_lio` 地图匹配。显式 `use_global_relocalizer:=false` 可回退旧后端。
