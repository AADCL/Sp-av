# 涵道四旋翼无人机开发实施文档

控制指令采用分步操作：`state=1` 只起飞并悬停，`state=2` 才开始／恢复任务，`state=3` 降落；悬停时收到新目标只加载，不自动执行。

2026-09-15：EGO 源码保留但运行冻结。当前 C++ `ducted_offboard` 将任务状态机和飞控执行器拆为独立模块与 20 Hz 线程，保持一个节点，仅支持直接限速航点跟踪，**没有自动避障**。1 起飞后悬停，2 执行／恢复任务，3 使用 PX4 AUTO.LAND 降落。

> 用途：说明当前系统的源码组织、配置、构建、模块实现及软件验证方法。  
> 写法：按阶段说明复制什么、打开什么、修改什么、编译什么、检查什么。  
> 平台：Orin NX、Ubuntu 20.04.6、ROS Noetic、MID360、PX4。文档版本V1.0，硬件配置核对日期2026-09-12，软件与文档更新日期2026-09-15。

## 8. 配置地图重定位

默认入口仍为 `ducted_bringup/relocalization.launch map_file:=/绝对路径/GlobalMap.pcd`。新增包 `ducted_localization` 移植 AG-TEST 的 FPFH/RANSAC + 点到面 ICP 流程；局部 FAST-LIO 继续提供 `camera_init/body` 位姿和 `camera_init` 点云。

主要文件：

~~~text
src/ducted_localization/config/global_relocalization.yaml
src/ducted_localization/src/ducted_localization/core.py
src/ducted_localization/src/ducted_localization/registration.py
src/ducted_localization/scripts/global_relocalizer.py
src/ducted_bringup/launch/relocalization.launch
~~~

| 参数 | 默认值 |
|---|---:|
| 粗/细体素 | 0.40 / 0.10 m |
| RANSAC 最大迭代 | 100000 |
| 最低 fitness / 最大 RMSE | 0.55 / 0.30 m |
| 子图积累 / 最少帧 / 最少点 | 3 s / 5 帧 / 500 点 |
| 独立确认次数 / 初始化超时 | 2 / 60 s |
| 跟踪周期 / 校正有效期 | 1 / 3 s |
| 最大校正变化 | 0.50 m / 0.35 rad |
| 连续跟踪失败限制 | 3 次 |
| 点云、里程计最大年龄 | 0.50 s |

自动初始化对每个新子图独立做全局解算；不使用上一次全局结果作为下一次确认的 ICP 初值。手动初值走 ICP，同样要求多次确认。`/ducted/relocalization/initialpose` 保留 `PoseWithCovarianceStamped` 类型，必须使用新鲜时间戳和 `map` frame，语义为机体中心。换算式为 `T_map_camera = T_map_base × T_base_body × inverse(T_camera_body)`，原雷达外参数值不变。

手动初值优先：新请求递增会话编号、终止旧工作进程，旧自动结果不能覆盖新请求。初始化仅允许基础层正常、传感器新鲜、飞控连接且未解锁时进行。`auto_initialize:=false` 只等待手动初值；`/ducted/relocalization/retry` 显式重新自动搜索，返回受理状态，最终定位结果通过 status 和 map_ready 判断。

成功后保持节点运行，约 1 Hz ICP 跟踪更新 `T_map_camera`；每条新鲜本地里程计乘以有效校正，发布同源时间戳的 map/body 里程计，交由既有 world_tf_owner 生成唯一 `map → odom`。实际位姿从 `/ducted/relocalization/pose` 获取（map/base_link）。点云或里程计过期立即撤销有效性；配准连续失败或校正过期也会失效，必须显式重新初始化。

重型配准在独立进程内运行，主节点使用单调时钟控制超时；局部 FAST-LIO 不随全局初始化重置。与 AG-TEST 相比，本实现使用 Python Open3D、机体中心初值补偿、可中断工作进程和既有 TF owner；不复制空地控制、地图管理服务或带错误消息类型的启动辅助脚本。

回退旧实现可指定 `use_global_relocalizer:=false`，此时才启动 `sfast_lio` 和 `relocalization_mid360.yaml`（雷达类型 4、NDT 参数及 init_threshold=0.1）。默认新后端复用局部 LIO 的建图配置（雷达类型 5），不再重复运行第二套 LIO。建图与重定位仍二选一。

## 9. 实现外部里程计链路

打开：

~~~text
src/ducted_bringup/src/ducted_bringup/fastlio_odometry.py
src/ducted_bringup/scripts/fastlio_odometry_adapter.py
src/ducted_bringup/config/external_odometry.yaml
src/ducted_bringup/launch/external_odometry.launch
~~~

处理顺序：

1. 检查基础/重定位就绪、frame、时间戳与数据有限性。
2. 将MID360内部IMU状态通过刚性安装关系转换为机体中心状态。
3. 使用初始化时锁定FCU的ENU姿态建立固定 `odom → camera_init`旋转。
4. 补偿安装杆臂带来的线速度，按机体frame表达输出速度。
5. 随建图/重定位启动的 `/localization_frames` 发布 `/ducted/localization/body_odom` 及同一时刻的TF。
6. `base_system.launch` 末尾默认包含 `external_odometry.launch`，传入 `input_contract_confirmed=true`；由转发节点校验基础就绪、定位就绪、坐标系和时效后原样转发到 `/mavros/odometry/out`，不发布TF。
7. MAVROS进行ENU/FLU到NED/FRD转换，使用MAVLink ODOMETRY送PX4。

原始FAST-LIO线速度按map表达，角速度按传感器frame表达；不能把旧twist数组直接当作目标坐标系中的速度。
源分支已经修正速度与协方差语义，适配器输出使用自身配置的暂定方差，不能把这些方差解释为实测统计精度。
MID360内部雷达—IMU平移只在算法内部使用一次。

`align_with_fcu=true`。独立转发入口的 `input_contract_confirmed` 默认false；基础层按本机已采用的定位链传入true。`start_external_odometry` 在基础层默认true，诊断时可显式设false。无有效定位数据时等待，不影响基础层硬件就绪。
预览时先用 `base_system.launch start_external_odometry:=false` 禁用默认转发，再单独启动转发入口并重映射到 `/ducted/external_odometry/preview`；这仍需要有效初始化条件。

## 10. 实现地面高度估计

打开：

~~~text
src/ducted_bringup/src/ducted_bringup/terrain_height.py
src/ducted_bringup/scripts/terrain_height_node.py
src/ducted_bringup/config/terrain_height.yaml
src/ducted_msgs/msg/TerrainHeight.msg
~~~

公共消息：

~~~text
std_msgs/Header header
float64 ground_z
float64 agl
float64 variance
bool valid
string reason
~~~

算法使用点云测量时刻的TF，将点云和机体参考点变换到竖直 `odom`。
局部平面拟合结合残差分组和支撑范围检查，避免把墙面、单侧支撑或台阶两层混合成地面。
TF采用有限等待，耗时处理在状态锁外进行，发布前重新检查输入代次和时效。

默认参考为 `base_link`中心。独立选择 `body_bottom`时按姿态旋转八顶点并取最低点；当前导航节点明确要求中心AGL，因此不能单边切换参考。
断流或无效数据清除可用性，源时间和单调到达时间共同参与判断。

关键限制：半径1 m、最少20点、最大源年龄0.25 s、位姿/点云时间差0.05 s、输出AGL范围0～4 m。

## 11. 实现遥控器处理

打开：

~~~text
src/ducted_control/src/ducted_control/rc.py
src/ducted_control/scripts/rc_monitor.py
src/ducted_control/config/rc.yaml
src/ducted_msgs/msg/RCState.msg
~~~

从 `/mavros/rc/in`读取，不增加独立串口接收器。
CH1～4采用本机读取到的1044～1944端点；CH2反向，油门输出0～1，其余主杆量输出-1～1。
模式与开关使用死区/滞回处理；无效PWM、重复/倒退时间戳、断流和基础层失效都撤销有效状态。

RCState发布的是状态电平，不是动作请求。首帧、重连首帧及开机高电平不触发动作。
`mapping_confirmed=false`为默认运行配置；CH7/8保留PX4自身解锁/急停职责。

## 12. C++ 任务状态机与飞控执行器

`ducted_offboard` 使用 C++14、roscpp、yaml-cpp；一个 ROS 节点，两个独立 20 Hz 循环：

| 模块 | 职责 |
|---|---|
| `include/ducted_offboard/types.hpp`、`src/types.cpp` | 公共位姿、限速与坐标转换 |
| `include/ducted_offboard/task_machine.hpp`、`src/task_machine.cpp` | 0/1/2/3 命令变化、启动先观察 0、任务列表与索引、到点连续判定、任务超时 |
| `include/ducted_offboard/execution.hpp`、`src/execution.cpp` | 内部请求/反馈契约；接管、解锁、起飞、限速跟踪、悬停、降落、锁定与独立时效门控 |
| `src/offboard_node.cpp` | ROS 输入、不可变快照交换、独立服务线程、有界异步日志、唯一 MAVROS 位置目标发布者 |

两层通过 `shared_ptr<const …>` 原子交换值快照，不共享任务列表。请求含任务代次、递增 ID、目标、单调时钟时间，反馈含确认编号、执行器起飞位置/航向及状态。执行器不访问命令参数，也不解析文件。任务循环的参数访问、任务解析和日志落盘不持有执行循环的长时间锁。

`task_timeout=0.5` 秒。失去任务心跳后撤销地面接管和解锁请求；空中定位有效且仍在 OFFBOARD 时捕获当前位置悬停，恢复任务线程后不自动续飞。落地流程已进入后仍由执行器完成。未派发的旧服务请求在工作线程发送前检查编号/时效，迟到响应不推进新请求；实际模式、解锁和落地反馈独立检查。

状态新增 `task_phase`、`executor_phase`、`task_generation`、`task_heartbeat_age`；既有规划字段固定 FROZEN、False、空编号、-1。默认目标推进为水平 0.3 m/s、竖直 0.2 m/s、yaw 20°/s；这些不是 PX4 AUTO.LAND 降落参数。

事件日志区分 `[Task]`、`[Executor]`，日志工作线程以最多 1024 条的队列异步写盘；优先丢弃遥测并报告丢弃数，文件按大小轮换。CSV 默认 5 Hz，同时记录两层阶段、心跳、实际与目标位姿。

## 13. EGO 运行冻结

`ducted_planning` 与 `ducted_navigation` 的算法源码、配置和离线单元测试保留。三个规划 launch 仅运行拒绝脚本 `ducted_bringup/scripts/frozen_ego.py`；模块组合选择规划也触发拒绝。EGO C++ 主函数与导航 Python 生产入口在构造节点前退出，不能通过 rosrun 绕过。

## 14. 任务输入与分步操作

任务源保留 file、param、topic，话题支持单点 PoseStamped 与序列 Path。默认 `mission_start` 由执行器确认的本轮起飞原点和航向转换到 `odom`；显式 odom 目标不再旋转，不增加公共 TF 边。

1 只接管、解锁、起飞后悬停；2 开始或恢复任务；0 暂停；3 中断任务并降落。悬停与暂停期间新目标只加载，执行中单点可以替换；序列只在等待/暂停时替换。到点依据实际位置、航向和速度连续满足阈值后推进，任务完成悬停等待降落命令。当前没有自动避障。

## 动态滤波与 EGO 局部规划实现补充

`ducted_mapping`移植AG-TEST的`StaticMapFilter`，保留Apache-2.0来源说明。新增严格递增扫描时间和有限参数检查；重复扫描不能伪造多帧静态支持。距离和半径过滤只作用于地图保存，不改动FAST-LIO在线状态估计或实时避障点云。

每个去畸变扫描经裁剪及体素处理后留档，记录`T_anchor_lidar`与时间。导出时按`T_map_anchor_optimized * T_anchor_lidar`重放，传感器射线原点使用同一变换；MID360内部外参仅在构造相对雷达位姿时应用一次。留档错误、容量超限或缺失优化锚点都会使导出失败。默认保存接口以暂存目录写全套文件，使用不覆盖的目录重命名发布；已有地图目录拒绝覆盖。

三维观测栅格由`export_occupancy:=true`按需启用，默认关闭以减少导出耗时；EGO不依赖它。启用时单独对原始扫描端点执行体素射线遍历，保存空闲／占据log-odds。缺席格点为未知，不能从静态PCD空洞推断空闲。动态滤波判出的瞬态点仍进入观测占据通道，只有后续自由空间证据才能清除。

EGO 历史算法源码保留于 `ducted_planning/vendor/ego`，来源与修改记录见 `PROVENANCE.md`。运行已冻结；这些历史算法不参与本版任务控制。动态地图滤波和保存功能继续运行。

保存性能与交互：`ducted_scan_archive`启用`-O2`（不启用fast-math），最多两个任务并行读取扫描、半径去噪和坐标变换，结果按扫描原顺序进入时间过滤器。队列有界，任何准备错误使整次导出失败。静态确认条件不变，原生地图体素改为5 cm；客户端默认不额外做20 cm降采样。`ScanArchive::replay`回调报告已处理/总扫描数；建图服务最多每秒更新`/ducted/mapping/save_progress`。后台客户端继承flock防止重复提交，状态文件原子更新。服务成功并按元数据核对文件后才写`SUCCEEDED`；连接异常标记`UNKNOWN`且不自动重试。同步服务仍会在导出期间阻塞建图处理，客户端后台化不改变这一点。

`mapping_metadata.yaml`格式v2明确包含`occupancy_exported`，记录实际输出分辨率、扫描档案目录、点数、并发数和导出耗时。客户端兼容v1七文件格式；v2只有显式`occupancy_exported: false`才允许缺少占据文件。FAST-LIO在线降采样、定位输入、机体外参和实时避障点云保持原配置。

工作空间根目录的 `save_map.sh` 是简化入口：根据脚本位置确定工作空间，加载 `devel/setup.bash`，调用 `save_map.py start --wait`。不传名称时自动生成时间戳目录；名称只能是单个目录名，目标限定在本工作空间 `maps/` 下，不提前创建目录，不覆盖已有地图。`./save_map.sh --status` 和 `./save_map.sh --wait` 分别查询和跟随最新任务。需要完整路径或自定义分辨率时，仍使用 Python 客户端。

`wait_for_save` 每2秒读取状态并显示服务端进度；成功打印地图路径，失败返回非零退出码。Ctrl+C 仅结束前台监视，独立会话中的后台保存继续。`read_status` 校验进程启动标识并识别僵尸进程，确认进程退出前重新读取最终状态，避免将刚完成的保存误报为 `UNKNOWN`。未知结果不自动重试；整个保存期间保持基础层和建图运行，机体静止。

保存客户端的11项检查覆盖完整文件包、失败、连接中断、进度、退出与完成竞争、僵尸进程和前台中断；远程独立 ROS master 的6项脚本检查覆盖自动加载环境、自动命名、查询、重新等待、防覆盖和非法路径。隔离检查使用临时测试地图，不代表一次真实现场地图导出。记录位于 `logs/map_save_shortcut_result.json`。


本版按运行阶段划分公共TF（2026-09-12更新）：

- 仅基础系统：无定位TF边，不出现`map`、`odom`、`camera_init`或`body`定位链；`base_link`为机体参考。
- 建图：`odom → camera_init → body → base_link`，不存在`map`。
- 重定位成功且源数据新鲜：`map → odom → camera_init → body → base_link`。

`camera_init → body`由独立的局部FAST-LIO发布。默认 `ducted_localization` 复用该局部点云，以 FPFH/RANSAC 完成未知位姿初始化，随后约 1 Hz 做点到面 ICP 地图跟踪。它把有效全局校正应用到每条新鲜局部里程计，保留完全相同的源时间戳，发布 `/ducted/relocalization/global_odom`（map/body）且不发布 TF。`world_tf_owner.py`按相同扫描时间戳配对全局与局部机体位姿，计算`T_map_odom = T_map_base × inverse(T_odom_base)`；全局校正不会重置局部FAST-LIO。数据过期或重定位无效时停止发布全局校正，`/ducted/localization/map_ready=false`。TF缓存可能短暂保留旧变换，不应只看树中是否还显示map判断定位有效。

`body`是MID360内部IMU参考，不是机体中心；`body → base_link`为原安装外参的逆变换，外参数值未改。保存PCD坐标沿用建图的`camera_init`数值，加载后将该固定地图坐标命名为`map`，建图时无需发布map TF。重定位RViz的Fixed Frame使用`map`；建图使用`odom`或`camera_init`。

MAVROS的ENU/NED、FLU/FRD辅助变换移至`/mavros/internal_tf_static`，其内部里程计转换仍使用这些变换，公共TF树不再出现辅助根。旧`odom → map`链已移除。默认重定位使用一个局部 FAST-LIO 和一个独立配准工作进程；不会同时启动旧 `sfast_lio` 地图匹配。显式 `use_global_relocalizer:=false` 可回退旧后端。
