远程主机就是涵道四旋翼主机，其他原有工作空间属于它自带的程序。
建图和重定位保留对应算法分支；本项目的硬件入口、坐标适配、地形、RC、飞控、规划与航点由新包统一管理。

| 内容 | 本项目处理 |
|---|---|
| MID360内部标定 | 建图/重定位采用一致的内部外参 |
| 原厂机体安装外参 | 复用 `[0.13,0,0]`与RPY `[0.03,0.4567,0]` |

| 原有飞控外环 | 使用PX4原生位置控制和新状态机 |

仓库中保留的原厂示例配置不代表运行入口。检查实际加载文件应使用 `roslaunch --files`或launch参数展开，不能只搜索所有YAML中的外参数值。

  - [-0.30,  0.35, -0.10]

## 9. 实现外部里程计链路

打开：

~~~text
src/ducted_bringup/src/ducted_bringup/fastlio_odometry.py
src/ducted_bringup/scripts/fastlio_odometry_adapter.py
src/ducted_bringup/config/external_odometry.yaml
src/ducted_bringup/launch/external_odometry.launch
~~~

处理顺序：

1. 检查基础/重定位就绪、frame、时间戳与数据有限性。
2. 将MID360内部IMU状态通过刚性安装关系转换为机体中心状态。
3. 使用初始化时锁定FCU的ENU姿态建立固定 `odom → camera_init`旋转。
4. 补偿安装杆臂带来的线速度，按机体frame表达输出速度。
5. 随建图/重定位启动的 `/localization_frames` 发布 `/ducted/localization/body_odom` 及同一时刻的TF。
6. 按需启动 `external_odometry.launch`，由 `external_odometry_relay.py` 校验门控、坐标系和时效后原样转发到 `/mavros/odometry/out`；转发节点不发布TF。
6. MAVROS进行ENU/FLU到NED/FRD转换，使用MAVLink ODOMETRY送PX4。

原始FAST-LIO线速度按map表达，角速度按传感器frame表达；不能把旧twist数组直接当作目标坐标系中的速度。
源分支已经修正速度与协方差语义，适配器输出使用自身配置的暂定方差，不能把这些方差解释为实测统计精度。
MID360内部雷达—IMU平移只在算法内部使用一次。

`align_with_fcu=true`，`input_contract_confirmed=false`。确认门控关闭时不发布有效外部里程计。
不需要FCU接收数据的转换查看可重映射到 `/ducted/external_odometry/preview`；这仍需要有效初始化条件。

## 10. 实现地面高度估计

打开：

~~~text
src/ducted_bringup/src/ducted_bringup/terrain_height.py
src/ducted_bringup/scripts/terrain_height_node.py
src/ducted_bringup/config/terrain_height.yaml
src/ducted_msgs/msg/TerrainHeight.msg
~~~

公共消息：

~~~text
std_msgs/Header header
float64 ground_z
float64 agl
float64 variance
bool valid
~~~

算法使用点云测量时刻的TF，将点云和机体参考点变换到竖直 `odom`。
局部平面拟合结合残差分组和支撑范围检查，避免把墙面、单侧支撑或台阶两层混合成地面。
TF采用有限等待，耗时处理在状态锁外进行，发布前重新检查输入代次和时效。

默认参考为 `base_link`中心。独立选择 `body_bottom`时按姿态旋转八顶点并取最低点；当前导航节点明确要求中心AGL，因此不能单边切换参考。
断流或无效数据清除可用性，源时间和单调到达时间共同参与判断。

关键限制：半径1 m、最少20点、最大源年龄0.25 s、位姿/点云时间差0.05 s、输出AGL范围0～4 m。

## 12. 实现飞控执行器

打开：

~~~text
src/ducted_control/src/ducted_control/flight.py
src/ducted_control/scripts/flight_controller.py
src/ducted_control/config/flight.yaml
src/ducted_msgs/msg/FlightSetpoint.msg
src/ducted_msgs/msg/FlightControlStatus.msg
src/ducted_msgs/srv/FlightCommand.srv
~~~

唯一执行链路为 `/ducted/control/target → flight_controller → /mavros/setpoint_position/local`。
目标使用 `odom`绝对位置、源时间戳及请求ID；位置和偏航参与控制，滚转/俯仰由PX4内部控制器生成。

主要状态：

~~~text
DISABLED → PRESTREAM → MODE_WAIT → HOLD / TRACK
                                  ├─ TAKEOFF
                                  ├─ HOLD_GRACE
                                  ├─ LAND_MODE_WAIT → LANDING
                                  └─ RELEASING
异常可进入 INHIBITED
~~~

20 Hz循环采用单调时间监视；模式服务有限排队并检查请求代次、截止时间和实际FCU反馈。
FCU与外部定位使用历史缓存按源时间配对，最大配对时间差0.05 s；不能拿不同测量时刻的最新消息直接比较。
默认飞行输出关闭，不自动解锁、接管、起飞或降落。

已实现的关键行为：

- 显式保持捕获实际位置并撤销旧请求；恢复必须使用不同ID及保持后的时间戳。
- RC保持能中断爬升；初始起飞请求需要RC指令模式。
- 最终输出同时满足速度和领先距离限制，无法兼容时撤销输出。
- 迟到的模式服务响应仍受原截止时间约束，未决服务结果不能被当作成功。
- 数据恢复后不自动重新接管。

## 13. EGO 局部规划与指令检查

打开：

~~~text
src/ducted_navigation/src/ducted_navigation/planner.py
src/ducted_navigation/src/ducted_navigation/runtime.py
src/ducted_navigation/scripts/ducted_navigation_node.py
src/ducted_navigation/config/local_avoidance.yaml
src/ducted_navigation/msg/NavigationStatus.msg
src/ducted_navigation/srv/Navigate.srv
~~~

`ego_planner.launch` 与 `local_avoidance.launch` 均启动同一 EGO 后端，二者只选一个。机体外接球覆盖姿态变化，并叠加制动、障碍净空和采样延迟余量。
障碍可短时保留并预测，目标更新限制完整三维速度变化，不只限制速度标量。
点云体素处理使用NumPy，邻域搜索可使用SciPy的cKDTree。

高度契约固定为：

~~~text
candidate_agl = measured_agl + candidate_z - current_z
target.z = absolute_odom_z
~~~

快照包含点云时刻的定位、中心AGL、控制器状态和请求代次。
耗时规划完成后，在最终状态锁内重新采样时间并核对输入；旧点云、被取消的目标或失效门控不能继续发布。
新有效心跳不应误取消当前目标，新目标/取消与点云代次变化则需要重新核对。

`geometry_confirmed`和`enable_output`默认false。默认体素0.08 m、速度0.5 m/s、竖直速度0.3 m/s。
持续无进展、障碍阻挡或数据失效触发有限保持后停止目标流，交由飞控执行器处理控制状态。

## 14. 实现航点任务

打开：

任务加载与执行分离。服务入口为 `/ducted/mission/start`、`pause`、`resume`、`cancel`。
启用任务指令后仍须显式调用start；任务不直接调用MAVROS，也不替代飞控engage或起飞流程。

实现要点：

1. 校验YAML坐标、姿态、容差和超时；map航点经完整TF转换，转换后再次检查工作范围。
2. 会话使用进程UUID和任务代次，避免重启后复用旧请求ID。
3. 到点要求实际位置、偏航、速度、连续停留、控制器TRACK状态和匹配请求ID。
4. 暂停/取消使旧代次失效；服务派发前再检查请求是否仍有效。
5. 服务工作进程提前预热，RPC有时限；撤销规划失败时仍尝试保持。
6. 末点完成先取消规划并确认保持，再报告任务成功。

任务模板允许map/odom，单点默认30 s，总任务120 s。模板坐标只是配置示例。

## 动态滤波与 EGO 局部规划实现补充

`ducted_mapping`移植AG-TEST的`StaticMapFilter`，保留Apache-2.0来源说明。新增严格递增扫描时间和有限参数检查；重复扫描不能伪造多帧静态支持。距离和半径过滤只作用于地图保存，不改动FAST-LIO在线状态估计或实时避障点云。

每个去畸变扫描经裁剪及体素处理后留档，记录`T_anchor_lidar`与时间。导出时按`T_map_anchor_optimized * T_anchor_lidar`重放，传感器射线原点使用同一变换；MID360内部外参仅在构造相对雷达位姿时应用一次。留档错误、容量超限或缺失优化锚点都会使导出失败。默认保存接口以暂存目录写全套文件，使用不覆盖的目录重命名发布；已有地图目录拒绝覆盖。

三维观测栅格单独对原始扫描端点执行体素射线遍历，保存空闲／占据log-odds。缺席格点为未知，不能从静态PCD空洞推断空闲。动态滤波判出的瞬态点仍进入观测占据通道，只有后续自由空间证据才能清除。

EGO 复用 `BsplineOptimizer`、`UniformBspline`、L-BFGS 和局部 `AStar`，来源、许可证和修改记录见 `ducted_planning/vendor/ego/PROVENANCE.md`。不使用上游全局路径管理器或飞行发送器；以实时点云快照构造局部占据体素。

EGO 内部 A* 只为当前曲线的碰撞段寻找回弹方向。上游近端三分之二检查扩展到完整种子和曲线，修复索引越界、搜索初值、优先队列和超时处理。统一缩放 B 样条结点时间，利用导数控制点约束连续速度、垂直速度和加速度。

规划服务接收同一时刻的 odom 起点、速度、绝对目标、完整障碍和 AGL 高度边界，不接收 map 变换。返回局部曲线与单独检查过的短距离位置参考。`TrajectoryGuard`继续限制实际位置步进、三维加速度和扫掠；快照过期或门控失效后禁止提交旧结果，RPC 最多一个在途请求。

`candidate_agl = measured_agl + candidate_z - current_z`保持不变。局部 AGL 包络随当前位置更新；当前地面估计不能证明远处坡面的净空，绝对定位 Z 不被替换。

新增隔离验证入口：

~~~bash
python3 src/ducted_bringup/test/integration/ego_core_isolated.py
python3 src/ducted_bringup/test/integration/ego_mission_isolated.py
~~~

两个脚本分别占用本机11325、11326端口；占用时拒绝启动。后者使用模拟FCU与当前机体尺寸，不能作为真实飞行记录。

保存性能与交互：`ducted_scan_archive`目标启用`-O2`（不启用fast-math），不改变过滤参数。`ScanArchive::replay`回调报告已处理/总扫描数；建图服务以最多每秒一次更新`/ducted/mapping/save_progress`。`save_map.py`以独立会话启动后台ROS客户端，继承flock防止重复后台提交，状态文件原子更新；提交不是保存成功，服务成功并验证七文件后才写`SUCCEEDED`。连接异常标记`UNKNOWN`且不自动重试。同步服务仍会在导出期间阻塞建图处理，客户端后台化不改变这一点。


本版按运行阶段划分公共TF（2026-09-11更新）：

- 仅基础系统：无定位TF边，不出现`map`、`odom`、`camera_init`或`body`定位链；`base_link`为机体参考。
- 建图：`odom → camera_init → body → base_link`，不存在`map`。
- 重定位成功且源数据新鲜：`map → odom → camera_init → body → base_link`。

`camera_init → body`由独立的局部FAST-LIO发布。重定位时额外运行局部scan-to-map里程计；原`sfast_lio`负责地图匹配，只发布`/ducted/relocalization/global_odom`（map/body）且不发布TF。`world_tf_owner.py`按相同扫描时间戳配对全局与局部机体位姿，计算`T_map_odom = T_map_base × inverse(T_odom_base)`；全局校正不会重置局部FAST-LIO。数据过期或重定位无效时停止发布全局校正，`/ducted/localization/map_ready=false`。TF缓存可能短暂保留旧变换，不应只看树中是否还显示map判断定位有效。

`body`是MID360内部IMU参考，不是机体中心；`body → base_link`为原安装外参的逆变换，外参数值未改。保存PCD坐标沿用建图的`camera_init`数值，加载后将该固定地图坐标命名为`map`，建图时无需发布map TF。重定位RViz的Fixed Frame使用`map`；建图使用`odom`或`camera_init`。

MAVROS的ENU/NED、FLU/FRD辅助变换移至`/mavros/internal_tf_static`，其内部里程计转换仍使用这些变换，公共TF树不再出现辅助根。旧`odom → map`链已移除。重定位阶段增加一个局部FAST-LIO进程，计算负载高于原单进程方案。

## 自动飞行组合（EGO）

入口 `automatic_flight.launch` 组合飞控执行器、EGO、航点任务和自动协调节点。基础层、建图或重定位、外部里程计、相对高度模块先按需启动。它与单独启动的飞控／导航／任务节点不能重复运行。

默认全部输出关闭。自动流程不调用解锁服务：操作员解锁后，收到明确启动请求才按“预发送与 OFFBOARD 接管 → 垂直起飞 → 航点任务 → 末点悬停或配置降落”执行。起飞目标为启动时绝对 odom Z 加 `takeoff_rise`（默认1.1 m）；航点本身仍配置绝对 map/odom 高度，不能把 h_agl 填进绝对 Z。

~~~bash
# 启动组合仅加载节点，默认不产生飞行输出
roslaunch ducted_bringup automatic_flight.launch \
  mission_file:=/home/nrc/catkin_ws/src/ducted_mission/config/mission.yaml
rostopic echo /ducted/automatic/status
~~~

实际执行需显式启用 `enable_commands:=true enable_flight_output:=true enable_navigation_output:=true geometry_confirmed:=true mapping_confirmed:=true`，并满足外部里程计、地形与遥控器自身门控；之后才可调用：

~~~bash
rosservice call /ducted/automatic/start "{}"
rosservice call /ducted/automatic/cancel "{}"
~~~

`finish:=hold` 是默认值；`finish:=land` 仅在航点任务成功且末点保持确认后请求 PX4 `AUTO.LAND`，并等待落地且未解锁反馈。不会因启动、重启、数据恢复或前一次完成自行开始新任务。

起飞前和爬升期间检查实时点云、机体竖直通道、倾角及数据新鲜度，按扫描时间匹配位姿历史并覆盖期间运动。RC 切回手动／保持、急停、数据中断、任务失败或取消会撤销自动序列；已进入 PX4 降落的取消不反向切回 OFFBOARD。普通取消捕获当前位置保持；数据或控制权失效时停止外部控制输出，由原飞控失效逻辑处理。

状态话题 `/ducted/automatic/status` 为 JSON 字符串，含 `state`、`reason`、`generation`、`target_z`、`finish`。`/ducted/automatic/flight_lease` 与 `mission_lease` 提供0.5秒心跳约束，组合中任一授权中断都会被对应执行器检查。服务超时不重试飞行动作，`FAULT` 闭锁阻止再次自动启动。

原 `waypoint_mission.launch` 仍适合已经接管并悬停后的单独航点操作。官方 EGO 来源和修改记录见 `catkin_ws/src/ducted_planning/vendor/ego/PROVENANCE.md`。
