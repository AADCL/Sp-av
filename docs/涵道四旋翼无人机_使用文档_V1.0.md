# 涵道四旋翼无人机使用文档

> 本文介绍现有系统的连接、检查、建图、保存、重定位、地面高度、遥控、飞控、避障、航点和记录操作。  
> 文档版本：V1.0；配置核对日期：2026-09-10。  
> 参数速查见《详细信息表》，源码与编译见《开发实施文档》。

## 1. 连接与检查

### 1.1 登录主控

~~~bash
ssh nrc@192.168.50.140
cd /home/nrc/catkin_ws
source devel/setup.bash
~~~

后续命令均在机载主控上执行。每新开一个SSH终端，都先执行 `source /home/nrc/catkin_ws/devel/setup.bash`。

### 1.2 网络、串口和时间

~~~bash
ip -brief -4 address
ping -c 2 192.168.1.109
ls -l /dev/ttyTHS0
groups
timedatectl show -p NTP -p NTPSynchronized -p Timezone
~~~

| 检查项 | 当前配置 |
|---|---|
| 无线地址 | `192.168.50.140/24` |
| 雷达接收地址 | eth0含 `192.168.1.50/24` |
| 雷达地址 | `192.168.1.109` |
| 飞控设备 | `/dev/ttyTHS0`，921600 baud |
| 串口权限 | `nrc`属于`dialout`，串口可读写 |
| 时间 | NTP启用且已同步；时区Asia/Shanghai |

### 1.3 确认模块运行情况

~~~bash
rosnode list
~~~

未启动ROS主站时，该命令报无法连接主站是正常现象。若已有节点，先核对其用途，再决定需要启动哪个模块，避免重复运行MAVROS、雷达、建图或重定位。

## 2. 启动基础层

终端A：

~~~bash
roslaunch ducted_bringup base_system.launch
~~~

基础层默认只启动MAVROS、MID360驱动和基础健康监视器。它是其他功能的共同前置，不发送飞行目标、模式切换或解锁指令。

终端B检查：

~~~bash
rostopic echo -n 1 /mavros/state
rostopic hz /livox/lidar
rostopic hz /livox/imu
rostopic echo -n 1 /ducted/system/ready
~~~

`rostopic hz`持续显示统计，按 `Ctrl+C` 结束该检查命令。
通过条件为飞控 `connected: true`、雷达数据持续更新、基础层持续发布 `data: true`。雷达点云配置10 Hz，RC实测约20 Hz；IMU以实际测得频率为准。

运行自动检查并保存结果：

~~~bash
mkdir -p /home/nrc/catkin_ws/logs
rosrun ducted_bringup startup_check.py --profile base \
  --output /home/nrc/catkin_ws/logs/startup_base_manual.json
~~~

检查器输出JSON，成功时 `passed=true`。它还检查RC传输、串口权限、MAVROS坐标转换TF和定位发布者是否重复。基础层的 `ready=true` 本身不代表飞控已取得控制权。

## 3. 建图与保存

### 3.1 启动建图

保持基础层运行，另开终端：

~~~bash
roslaunch ducted_bringup mapping.launch
~~~

`mapping.launch`不包含雷达或MAVROS。默认等待基础就绪最多15秒，未就绪时退出。

检查：

~~~bash
rostopic hz /ducted/localization/odom
rostopic hz /ducted/mapping/cloud_registered
rostopic echo -n 1 /ducted/localization/odom/header
rostopic echo -n 1 /ducted/localization/odom/child_frame_id
rosrun tf tf_echo map livox_frame
~~~

期望 `header.frame_id=map`、`child_frame_id=livox_frame`，点云和里程计持续更新。
需要可视化时运行 `rviz`，Fixed Frame设为 `map`，添加 `/ducted/mapping/cloud_registered` 的PointCloud2和 `/ducted/localization/path` 的Path显示。

### 3.2 采集与坐标理解

采集应覆盖墙面、门框、转角等三维结构，保持雷达安装固定，尽量从不同方向观察相同区域。
建图输出的Z属于固定 `map` 坐标；原始地图轴可能倾斜，不直接将其Z当作竖直离地高度。

### 3.3 显式保存地图

在建图节点仍运行时，新建一个地图目录，再调用保存服务。以下目录名仅作示例；每次采集使用独立目录。

~~~bash
mkdir -p /home/nrc/catkin_ws/maps/site_a
rosservice call /ducted/mapping/save_map \
  "resolution: 0.2
destination: '/home/nrc/catkin_ws/maps/site_a'"
~~~

等待服务返回 `success: true`，然后检查：

~~~bash
find /home/nrc/catkin_ws/maps/site_a -maxdepth 1 -type f \
  -printf '%f %s bytes\n' | sort
~~~

本例 `resolution=0.2` 应生成：

~~~text
trajectory.pcd
transformations.pcd
SurfMap.pcd
filterGlobalMap.pcd
GlobalMap.pcd
~~~

确认文件已写入后，才在建图终端按 `Ctrl+C`。当前配置不在退出时自动保存，也不需要轮式系统的 `finalize_map.py`。
保存服务的成功标志对应 `GlobalMap.pcd` 的写入结果，因此还要检查其他文件是否存在、大小是否合理。再次写入同一目录会覆盖同名文件。

## 4. 加载地图与重定位

### 4.1 启动

先停止建图，保持基础层运行：

~~~bash
roslaunch ducted_bringup relocalization.launch \
  map_file:=/home/nrc/catkin_ws/maps/site_a/GlobalMap.pcd
~~~

若复用已记录的验证场景，路径为：

~~~text
/home/nrc/catkin_ws/maps/step6_validation_20260910/GlobalMap.pcd
~~~

地图必须与当前场景对应。省略 `map_file` 会读取 `/home/nrc/catkin_ws/maps/GlobalMap.pcd`，不会自动寻找最新地图。

### 4.2 设置初始位姿

运行 `rviz`，Fixed Frame设为 `map`。
在Tool Properties中，把 **2D Pose Estimate** 的Topic改成 `/ducted/relocalization/initialpose`，再指定地图中的位置和机头方向。
同时显示 `/ducted/relocalization/global_map` 和 `/ducted/relocalization/registered_scan`，观察当前点云与地图是否重合。

2D工具主要给出平面位置和朝向；需要完整三维初值时，使用 `geometry_msgs/PoseWithCovarianceStamped`，坐标系设为 `map`。

### 4.3 检查重定位

~~~bash
rostopic echo -n 1 /ducted/relocalization/ready
rostopic echo -n 1 /ducted/relocalization/registered_scan/header
rostopic hz /ducted/localization/odom
rosrun ducted_bringup startup_check.py --profile localization \
  --output /home/nrc/catkin_ws/logs/startup_localization_manual.json
~~~

`/ducted/relocalization/ready`必须有效且持续更新；仅有里程计消息不等于地图匹配已成功。
启动检查的localization档验证源里程计和基础依赖，重定位质量仍须查看就绪话题和匹配日志。

## 5. 外部里程计与相对地面高度

### 5.1 数据链路

~~~text
FAST-LIO /Odometry
  → launch重映射为 /ducted/localization/odom
  → fastlio_odometry_adapter.py
  → /mavros/odometry/out
  → MAVROS ENU/FLU 到 NED/FRD 转换
  → PX4 MAVLink ODOMETRY
~~~

`/mavros/odometry/out`是本系统从ROS向PX4送入外部里程计的入口。
适配器需要基础层、重定位就绪以及初始化时锁定飞控的姿态。它补偿传感器安装关系，并建立 `odom → map → livox_frame → base_link` 主链。

### 5.2 默认启动

~~~bash
roslaunch ducted_bringup external_odometry.launch
~~~

默认 `input_contract_confirmed=false`，不会输出有效外部里程计。此时查看日志及门控状态；没有输出属于配置规定的行为。

需要只检查转换结果而不送入MAVROS时，可在安装契约成立的条件下使用预览话题：

~~~bash
roslaunch ducted_bringup external_odometry.launch \
  input_contract_confirmed:=true \
  output_odom:=/ducted/external_odometry/preview
~~~

这会发布有效适配结果和TF，但输出被重映射到预览话题。不要与另一份适配器同时运行。
正式外部里程计入口使用默认 `output_odom=/mavros/odometry/out`；启用确认参数后会向PX4注入定位数据。

检查预览：

~~~bash
rostopic echo -n 1 /ducted/external_odometry/preview
rosrun tf tf_echo odom base_link
~~~

输出应为 `header.frame_id=odom`、`child_frame_id=base_link`。

### 5.3 启动地面高度

保持重定位及有效适配TF运行：

~~~bash
roslaunch ducted_bringup terrain_height.launch
~~~

默认 `reference_confirmed=false`，高度消息会保持无效。参考配置采用机体中心；显式确认该配置的运行方式为：

~~~bash
roslaunch ducted_bringup terrain_height.launch reference_confirmed:=true
~~~

以上是同一模块的两种启动方式，选择其一。

~~~bash
rostopic echo /ducted/terrain/height
rostopic echo -n 1 /ducted/terrain/ready
rosrun ducted_bringup startup_check.py --profile terrain \
  --output /home/nrc/catkin_ws/logs/startup_terrain_manual.json
~~~

| 字段 | 解释 |
|---|---|
| `header.frame_id` | `odom`，竖直对齐后的固定坐标 |
| `ground_z` | 拟合地面在该坐标系中的高度 |
| `agl` | 默认机体中心到地面的竖直距离 |
| `variance` | 高度估计方差 |
| `valid` | 当前估计是否可用；false时不能使用保留数值 |

机体总高20 cm、原点居中。水平姿态下机底离地高度为 `agl - 0.10 m`。
当前避障接口要求 `base_link`中心AGL；不要仅把地形模块改为 `body_bottom` 后仍接入原避障配置。
点云断流、位姿超时、TF缺失、地面支撑不足或台阶多层歧义都会使高度无效。

## 6. 遥控器与飞控模块

### 6.1 查看遥控器

基础层已经提供原始RC数据：

~~~bash
rostopic echo -n 1 /mavros/rc/in
rostopic hz /mavros/rc/in
~~~

需要解码状态时：

~~~bash
roslaunch ducted_bringup rc_processing.launch
~~~

~~~bash
rostopic echo /ducted/rc/state
~~~

默认映射门控关闭，解码状态保持无效并闭锁。CH1～4采用读取到的PX4标定，CH2反向；通道用途见《详细信息表》。CH7、CH8分别由PX4负责解锁与急停。

### 6.2 启动飞控执行器

~~~bash
roslaunch ducted_bringup flight_control.launch
~~~

此入口默认包含RC监视，不要再单独启动一份。如果已有RC节点，可使用 `start_rc_monitor:=false`。

~~~bash
rostopic echo /ducted/control/status
rostopic echo -n 1 /ducted/control/ready
~~~

默认 `enable_flight_output=false`，不会发送飞行目标。启动节点本身不会接管或解锁。
启用输出需要显式设置飞控输出和RC映射参数，并满足持续有效的定位、遥控、FCU状态及数值一致性检查。

### 6.3 控制服务

~~~bash
rosservice type /ducted/control/command
rossrv show ducted_msgs/FlightCommand
~~~

服务请求为 `command` 和 `target`，响应为 `accepted`、`message`。

| command | 行为 |
|---|---|
| `engage` | 捕获当前位置，预发送目标，再按反馈进入OFFBOARD；要求FCU已解锁，软件不代为解锁 |
| `hold` | 保持实际位置，撤销旧目标请求；保持状态仍可能拥有OFFBOARD控制权 |
| `takeoff` | 在已接管状态下，使用新鲜 `odom` 目标的绝对Z；要求ON_GROUND反馈，维持当前XY与航向 |
| `land` | 请求AUTO.LAND并等待实际模式/着陆反馈 |
| `release` | 请求释放OFFBOARD控制权，跟踪模式反馈 |
| `reset` | 清除满足复位条件的锁存闭锁，不自动接管 |

例如请求保持：

~~~bash
rosservice call /ducted/control/command \
  "command: 'hold'
target:
  header: {frame_id: 'odom'}
  pose:
    position: {x: 0.0, y: 0.0, z: 0.0}
    orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}"
~~~

`hold`不使用示例中的目标位置，而是捕获实际位置。默认关闭输出时服务会拒绝请求；`accepted=true`也只表示接受转换请求，最终行为须查看状态反馈。
`takeoff`目标需要当前时间戳，不能复制固定时间的请求长期使用。

## 7. 局部避障与航点任务

### 7.1 启动局部避障

~~~bash
roslaunch ducted_bringup local_avoidance.launch
~~~

~~~bash
rostopic echo /ducted/navigation/status
rostopic info /ducted/navigation/preview
rossrv show ducted_navigation/Navigate
~~~

默认输出与几何确认门控均关闭。实际输出依赖新鲜点云、中心AGL、外部定位和已就绪的飞控执行器；仅启动节点不会运动。
机体包络已使用60×70×20 cm的中心长方体。规划器输出绝对位置，地面高度仅用于检查候选位置的离地净空。

| 导航状态 | 含义 |
|---|---|
| `IDLE` | 无活动目标 |
| `CLEAR` | 可沿当前方向推进 |
| `AVOIDING` | 正在选择绕障方向 |
| `BLOCKED` | 当前没有满足碰撞/运动约束的推进目标 |
| `STALE_INPUT` | 数据、就绪条件或快照失效 |
| `GOAL_REACHED` | 规划到点状态，任务仍核对实际位姿和停留 |

`/ducted/navigation/command`支持 `goal`和`cancel`。目标为带新鲜时间戳的 `PoseStamped`，请求必须有唯一ID；取消使用对应活动ID。
局部避障只向 `/ducted/control/target`发送目标，不直接调用MAVROS模式服务。

### 7.2 配置航点文件

模板位置：

~~~text
/home/nrc/catkin_ws/src/ducted_mission/config/mission.yaml
~~~

每个航点包含坐标系、绝对位置和偏航角，例如：

~~~yaml
waypoints:
  - frame_id: map
    position: [0.0, 0.0, 1.0]
    yaw: 0.0
  - frame_id: map
    position: [1.0, 0.0, 1.0]
    yaw: 0.0
~~~

这是字段示例，不是可直接用于任意场地的航线。完整配置还包括 `mission_id`、`workspace`、容差和超时；保留模板中的完整结构。
`map`目标经完整TF转换到 `odom`，不能只更改坐标系名称。

### 7.3 启动与操作

~~~bash
roslaunch ducted_bringup waypoint_mission.launch \
  mission_file:=/home/nrc/catkin_ws/src/ducted_mission/config/mission.yaml
~~~

~~~bash
rostopic echo /ducted/mission/status
~~~

默认 `enable_commands=false`。加载任务文件不会自动执行任务、接管、起飞或降落。
任务指令启用、上游就绪且控制权成立后，可使用以下服务；每次按需要调用一条：

~~~bash
rosservice call /ducted/mission/start '{}'
rosservice call /ducted/mission/pause '{}'
rosservice call /ducted/mission/resume '{}'
rosservice call /ducted/mission/cancel '{}'
~~~

服务返回 `success`和`message`。暂停/取消涉及撤销规划并请求保持；恢复创建新请求ID。
到点判断同时检查实际位置、航向、速度、停留时间和控制器请求ID。最后一个航点完成后请求保持，收到相应结果才报告成功。

## 8. 按需组合启动

基础层始终单独运行。其余模块可组合，例如重定位和数据记录：

~~~bash
roslaunch ducted_bringup modules.launch \
  localization:=relocalization \
  map_file:=/home/nrc/catkin_ws/maps/site_a/GlobalMap.pcd \
  start_recording:=true
~~~

| 参数 | 可用值或作用 |
|---|---|
| `localization` | `none`、`mapping`、`relocalization` |
| `start_external_odometry` | 里程计适配器 |
| `start_terrain` | 地面高度 |
| `start_rc_processing` | RC处理 |
| `start_flight` | 飞控执行器，包含RC处理 |
| `start_avoidance` | 局部避障 |
| `start_mission` | 航点任务 |
| `start_recording` | 数据记录 |

所有 `start_*`默认false。模块组合不会自动打开确认和输出门控。
组合参数中，导航输出名为 `enable_navigation_output`，任务指令名为 `enable_mission_commands`；它们分别转发给子launch的 `enable_output`、`enable_commands`。
建图组合不产生重定位质量就绪信号，不能直接替代当前外部里程计链路要求的重定位前置。

## 9. 日志和数据记录

基础层就绪后启动：

~~~bash
roslaunch ducted_bringup recording.launch
~~~

记录器收到两次近期有效基础心跳后，在 `logs/recordings`下创建UTC时间加UUID目录。
会话包含选定话题的bag、参数快照和退出信息。运行后基础层丢失时继续记录，以保留故障前后数据。

需要完整参数副本时，在业务节点全部加载后另外执行：

~~~bash
rosparam dump /home/nrc/catkin_ws/logs/runtime_params.yaml
~~~

此命令写入独立参数文件；记录器自身的 `session.json`仅包含选定命名空间的快照。

停止记录终端，等待写入索引和正常退出，再检查对应文件：

~~~bash
find /home/nrc/catkin_ws/logs/recordings -maxdepth 2 -type f \
  -printf '%p %s bytes\n'
~~~

对所选会话中的实际bag执行 `rosbag info /实际路径/telemetry_0.bag`。`.active`仍存在时不应把会话视为已经正常收尾。

## 10. 停止顺序

对于数据查看、建图或默认关闭输出的模块：

1. 建图模式先调用保存服务，检查文件后停止建图。
2. 停止任务、避障和飞控等上层模块。
3. 停止地形、适配器和重定位。
4. 停止基础层，记录器可继续保留这段退出过程。
5. 最后停止记录器，等待bag收尾，使用 `rosnode list`核对。

若飞控正在拥有实际控制权，先完成对应的保持、释放或降落状态转换，再结束节点。`Ctrl+C`只是停止进程，不是降落指令；也不要使用轮式机器人的零速度话题代替本系统控制服务。

## 11. 快速排错

| 现象 | 首先检查 |
|---|---|
| 雷达无数据 | eth0的192.168.1.50、雷达192.168.1.109、驱动配置和节点 |
| MAVROS断连 | ttyTHS0、921600、权限、FCU供电与连接 |
| 基础层退出或不就绪 | `/diagnostics`、MAVROS状态、雷达数据年龄 |
| 建图或重定位无输出 | 基础层先启动、Livox点云/IMU、初始化日志 |
| 地图不匹配 | `map_file`、当前场景、RViz初值话题和方向 |
| 适配器无输出 | 确认门控、重定位就绪、初始化FCU姿态、frame和时效 |
| 地面高度无效 | 参考门控、精确时刻TF、中心参考、地面支撑、断流 |
| RC闭锁 | `mapping_confirmed`、原始通道、急停电平、超时 |
| 飞控不接管 | `enable_flight_output`、RC模式、FCU状态、数值一致性、`reason` |
| 任务暂停 | 导航/飞控状态、AGL有效性、请求ID、输入年龄 |
| 地图文件不全 | 保存是否在节点运行时调用、目录是否存在、分辨率是否大于0 |

配套文档：[详细信息表](涵道四旋翼无人机_详细信息表_V1.0.md)、[开发实施文档](涵道四旋翼无人机_开发实施文档_V1.0.md)。
