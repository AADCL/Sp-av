# 涵道四旋翼无人机使用文档

> 本文介绍现有系统的连接、检查、建图、保存、重定位、地面高度、遥控、飞控、避障、航点和记录操作。  
> 文档版本：V1.0；配置核对日期：2026-09-12。
> 参数速查见《详细信息表》，源码与编译见《开发实施文档》。

## 1. 连接与检查

### 1.1 登录主控

~~~bash
ssh nrc@192.168.50.140
cd /home/nrc/catkin_ws
source devel/setup.bash
~~~

后续命令均在机载主控上执行。每新开一个SSH终端，都先执行 `source /home/nrc/catkin_ws/devel/setup.bash`。

### 1.2 网络、串口和时间

~~~bash
ip -brief -4 address
ping -c 2 192.168.1.109
ls -l /dev/ttyTHS0
groups
timedatectl show -p NTP -p NTPSynchronized -p Timezone
~~~

| 检查项 | 当前配置 |
|---|---|
| 无线地址 | `192.168.50.140/24` |
| 雷达接收地址 | eth0含 `192.168.1.50/24` |
| 雷达地址 | `192.168.1.109` |
| 飞控设备 | `/dev/ttyTHS0`，921600 baud |
| 串口权限 | `nrc`属于`dialout`，串口可读写 |
| 时间 | NTP启用且已同步；时区Asia/Shanghai |

### 1.3 确认模块运行情况

~~~bash
rosnode list
~~~

未启动ROS主站时，该命令报无法连接主站是正常现象。若已有节点，先核对其用途，再决定需要启动哪个模块，避免重复运行MAVROS、雷达、建图或重定位。

## 2. 启动基础层

终端A：

~~~bash
roslaunch ducted_bringup base_system.launch
~~~

基础层默认启动MAVROS、MID360驱动、基础健康监视器和等待定位数据的外部里程计转发。它是其他功能的共同前置，不发送飞行目标、模式切换或解锁指令。

终端B检查：

~~~bash
rostopic echo -n 1 /mavros/state
rostopic hz /livox/lidar
rostopic hz /livox/imu
rostopic echo -n 1 /ducted/system/ready
~~~

`rostopic hz`持续显示统计，按 `Ctrl+C` 结束该检查命令。
通过条件为飞控 `connected: true`、雷达数据持续更新、基础层持续发布 `data: true`。雷达点云配置10 Hz，RC实测约20 Hz；IMU以实际测得频率为准。

运行自动检查并保存结果：

~~~bash
mkdir -p /home/nrc/catkin_ws/logs
rosrun ducted_bringup startup_check.py --profile base \
  --output /home/nrc/catkin_ws/logs/startup_base_manual.json
~~~

检查器输出JSON，成功时 `passed=true`。它还检查RC传输、串口权限、MAVROS坐标转换TF和定位发布者是否重复。基础层的 `ready=true` 本身不代表飞控已取得控制权。

## 3. 建图与保存

### 3.1 启动建图

保持基础层运行，另开终端：

~~~bash
roslaunch ducted_bringup mapping.launch
~~~

`mapping.launch`不包含雷达或MAVROS。默认等待基础就绪最多15秒，未就绪时退出。

检查：

~~~bash
rostopic hz /ducted/localization/odom
rostopic hz /ducted/mapping/cloud_registered
rostopic echo -n 1 /ducted/localization/odom/header
rostopic echo -n 1 /ducted/localization/odom/child_frame_id
rosrun tf tf_echo odom base_link
~~~

期望 `header.frame_id=camera_init`、`child_frame_id=body`，点云和里程计持续更新。
需要可视化时运行 `rviz`，Fixed Frame设为 `odom`（或`camera_init`），添加 `/ducted/mapping/cloud_registered` 的PointCloud2和 `/ducted/localization/path` 的Path显示。

`base_system.launch` 已包含外部里程计转发。建图定位就绪后，数据自动送入 PX4，无需再启动 `external_odometry.launch`。
检查 `/ducted/external_odometry/ready` 为 `true`、`/mavros/odometry/out` 持续发布，及 `/mavros/estimator_status` 中水平位置与速度有效。由操作员确认遥控器 kill 状态并尝试切换 Position。建图期间不需要 `map` 坐标系。

### 3.2 采集与坐标理解

采集应覆盖墙面、门框、转角等三维结构，保持雷达安装固定，尽量从不同方向观察相同区域。
建图原始点云的Z属于固定 `camera_init` 坐标；原始轴可能倾斜，不直接将其Z当作竖直离地高度。

### 3.3 显式保存地图

在建图节点仍运行时，执行工作空间根目录的脚本。脚本自动加载 ROS 环境、按时间生成尚不存在的地图目录，并显示后台保存进度。

基础系统与建图仍需保持运行，机体保持静止；后台化不意味着可以停止建图。

~~~bash
cd /home/nrc/catkin_ws
./save_map.sh
~~~

地图保存在 `maps/map_时间戳/GlobalMap.pcd`。需要指定名称时使用 `./save_map.sh site_b`，保存到 `maps/site_b/`；已有目录会拒绝覆盖，不要提前创建目标目录。默认分辨率0.2 m。

Ctrl+C 只退出进度显示，后台保存继续。查询最新保存任务或重新显示进度：

~~~bash
./save_map.sh --status
./save_map.sh --wait
~~~

`SUBMITTED`表示已提交，`SAVING`表示处理中；新版建图节点还会提供`completed/total`扫描进度与`FILTERING/WRITING`阶段。只有`SUCCEEDED`表示服务成功且七个文件齐全。`FAILED`查看建图终端和任务目录中的`worker.log`；`UNKNOWN`表示连接中断等原因使结果无法确认，应检查目标目录与服务端后再决定是否重试。程序不会自动重试。旧版运行中节点可使用后台命令，但没有逐帧进度。

原 Python 客户端继续支持自定义分辨率和完整路径：`rosrun ducted_bringup save_map.py start --destination /完整/新目录 --resolution 0.2`。程序打印的Job目录保存状态和日志；Python客户端查询历史任务可加`--job /完整/Job/目录`。同一ROS主站拒绝重叠的后台保存请求，不要同时手动调用旧保存服务。

传统同步`rosservice call /ducted/mapping/save_map`接口继续保留。后台客户端同样调用这个服务，过滤期间建图更新仍会暂停。地图处理库启用`-O2`优化，过滤阈值和观测占据规则不变。

等待状态为`SUCCEEDED`，然后检查：

~~~bash
find /home/nrc/catkin_ws/maps/site_b -maxdepth 1 -type f \
  -printf '%f %s bytes\n' | sort
~~~

本例 `resolution=0.2` 应生成：

~~~text
trajectory.pcd
transformations.pcd
SurfMap.pcd
filterGlobalMap.pcd
GlobalMap.pcd
observed_occupancy.pcd
mapping_metadata.yaml
~~~

确认文件已写入后，才在建图终端按 `Ctrl+C`。当前配置不在退出时自动保存，也不需要轮式系统的 `finalize_map.py`。
默认动态过滤模式下，成功标志要求整套文件完成写入。已有目录会被拒绝，不能覆盖旧地图。保存可能需要重放多帧扫描，调用期间应保持机体静止，等待结果后再退出。

动态过滤需要同一体素至少8帧命中、累计观测跨度至少2秒；移动后离开的物体还需要后续射线穿过其原位置才能清除。过滤只作用于保存的静态地图，在线定位和实时避障仍接收完整点云；它不保证移除静止很久的人或完全被遮挡的物体。原地图关键帧与扫描同步按回环优化位姿重放。扫描档案位于 `logs/mapping-scans-*`，每次建图默认上限2 GiB；空间或帧数超限时保存会报错，避免输出缺帧地图。

## 4. 加载地图与重定位

### 4.1 启动

先停止建图，保持基础层运行：

~~~bash
roslaunch ducted_bringup relocalization.launch \
  map_file:=/home/nrc/catkin_ws/maps/site_b/GlobalMap.pcd
~~~

若复用已记录的验证场景，路径为：

~~~text
/home/nrc/catkin_ws/maps/step6_validation_20260910/GlobalMap.pcd
~~~

地图必须与当前场景对应。省略 `map_file` 会读取 `/home/nrc/catkin_ws/maps/GlobalMap.pcd`，不会自动寻找最新地图。

### 4.2 自动搜索与手动初始位姿

默认自动搜索未知位置和姿态，无需先点击 RViz。保持飞机未解锁、基础层和雷达数据正常；程序累计多帧点云，通过 FPFH/RANSAC 全局匹配、点到面 ICP 精配准，并要求两次独立结果一致。初始化默认限时 60 s。成功后终端打印 `success=true`、`pose=(x,y,z)`、姿态四元数、`fitness` 和 `rmse`，坐标为 `map` 下的机体中心 `base_link`。

成功后保持本终端运行：FAST-LIO 持续输出局部里程计，全局节点约每秒做一次 ICP 地图跟踪，既有 TF 节点持续维护 `map → odom`。初始化成功不代表 launch 已执行结束。

自动失败或需要指定起点时，仍可使用下面的 RViz 操作；有效手动初值会中断当前自动搜索，优先执行手动初始化。仅允许在未解锁且数据新鲜时重新初始化。

运行 `rviz`，Fixed Frame设为 `map`。
在Tool Properties中，把 **2D Pose Estimate** 的Topic改成 `/ducted/relocalization/initialpose`，再指定地图中的位置和机头方向。
同时显示 `/ducted/relocalization/global_map` 和 `/ducted/relocalization/registered_scan`，观察当前点云与地图是否重合。

2D工具主要给出平面位置和朝向，默认 Z 为 0；这里的初值表示机体中心，不是雷达原点，节点会补偿原有安装外参。高度差较大或地图坐标倾斜时，使用带正确 Z/姿态和当前时间戳的 `geometry_msgs/PoseWithCovarianceStamped`，坐标系设为 `map`。

只使用手动初始化时，在启动命令末尾增加 `auto_initialize:=false`。需要重新自动搜索时，在未解锁状态执行：

~~~bash
rosservice call /ducted/relocalization/retry "{}"
~~~

该服务的 `success: true` 表示请求已受理；最终匹配结果查看状态话题。点云/里程计过期、跟踪校正过期或连续跟踪失败会撤销定位有效性，不会悄悄重新搜索。

### 4.3 检查重定位

~~~bash
rostopic echo -n 1 /ducted/relocalization/ready
rostopic echo /ducted/relocalization/status
rostopic echo /ducted/localization/map_ready
rostopic echo -n 1 /ducted/relocalization/registered_scan/header
rostopic hz /ducted/localization/odom
rosrun ducted_bringup startup_check.py --profile localization \
  --output /home/nrc/catkin_ws/logs/startup_localization_manual.json
~~~

`/ducted/relocalization/status` 包含 `state/source/success/reason/position/quaternion_xyzw/fitness/rmse`；有效状态为 `TRACKING`，来源为 `AUTO` 或 `MANUAL`。`/ducted/relocalization/ready` 与 `/ducted/localization/map_ready` 必须有效且持续更新；仅有局部里程计消息不等于地图匹配已成功。
启动检查的localization档验证源里程计和基础依赖，重定位质量仍须查看就绪话题和匹配日志。

## 5. 外部里程计与相对地面高度

### 5.1 数据链路

~~~text
FAST-LIO /Odometry
  → launch重映射为 /ducted/localization/odom
  → fastlio_odometry_adapter.py（随建图/重定位启动，发布完整TF）
  → /ducted/localization/body_odom
  → external_odometry_relay.py（随基础层启动，等待有效定位后发送）
  → /mavros/odometry/out
  → MAVROS ENU/FLU 到 NED/FRD 转换
  → PX4 MAVLink ODOMETRY
~~~

`/mavros/odometry/out`是本系统从ROS向PX4送入外部里程计的入口。
适配器随建图或重定位自动启动，需要基础层就绪和有效定位数据；重定位初始化成功仅决定全局`map → odom`校正是否可用，局部链可独立工作。坐标对齐需要新鲜的未解锁飞控姿态。它补偿传感器安装关系，并建立 `odom → camera_init → body → base_link` 主链。

### 5.2 随基础层自动启动

基础层末尾包含 `external_odometry.launch` 并设置 `input_contract_confirmed=true`。仅启动基础层时，转发节点等待定位；启动建图或重定位、局部定位链有效后，自动向 `/mavros/odometry/out` 发送。节点启动顺序由就绪门控协调，不依赖 launch 文件中的书写顺序。

~~~bash
rostopic echo -n 1 /ducted/external_odometry/ready
rostopic hz /mavros/odometry/out
~~~

输出应为 `header.frame_id=odom`、`child_frame_id=base_link`。不要再单独启动同名转发节点。

若只想查看转换结果而不送给 PX4，在启动基础层时禁用自动转发，再另开终端启动预览：

~~~bash
roslaunch ducted_bringup base_system.launch start_external_odometry:=false
~~~

保持基础层及建图/重定位运行，在另一个终端执行：

~~~bash
roslaunch ducted_bringup external_odometry.launch \
  input_contract_confirmed:=true \
  output_odom:=/ducted/external_odometry/preview
~~~

独立 `external_odometry.launch` 的确认参数默认仍为 `false`；日常使用由基础层传入 `true`。安装补偿和 TF 适配器仍由建图或重定位负责，转发节点不创建定位 TF。

### 5.3 启动地面高度

保持重定位及有效适配TF运行：

~~~bash
roslaunch ducted_bringup terrain_height.launch
~~~

默认 `reference_confirmed=false`，高度消息会保持无效。参考配置采用机体中心；显式确认该配置的运行方式为：

~~~bash
roslaunch ducted_bringup terrain_height.launch reference_confirmed:=true
~~~

以上是同一模块的两种启动方式，选择其一。

~~~bash
rostopic echo /ducted/terrain/height
rostopic echo -n 1 /ducted/terrain/ready
rosrun ducted_bringup startup_check.py --profile terrain \
  --output /home/nrc/catkin_ws/logs/startup_terrain_manual.json
~~~

| 字段 | 解释 |
|---|---|
| `header.frame_id` | `odom`，竖直对齐后的固定坐标 |
| `ground_z` | 拟合地面在该坐标系中的高度 |
| `agl` | 默认机体中心到地面的竖直距离 |
| `variance` | 高度估计方差 |
| `valid` | 当前估计是否可用；false时不能使用保留数值 |
| `reason` | 无效原因；接地参考不会改变本话题的有效性 |

机体总高20 cm、原点居中。水平姿态下机底离地高度为 `agl - 0.10 m`。
当前避障接口要求 `base_link`中心AGL；不要仅把地形模块改为 `body_bottom` 后仍接入原避障配置。
点云断流、位姿超时、TF缺失、地面支撑不足或台阶多层歧义都会使高度无效。

## 6. 遥控器与飞控模块

### 6.1 查看遥控器

基础层已经提供原始RC数据：

~~~bash
rostopic echo -n 1 /mavros/rc/in
rostopic hz /mavros/rc/in
~~~

需要解码状态时：

~~~bash
roslaunch ducted_bringup rc_processing.launch
~~~

~~~bash
rostopic echo /ducted/rc/state
~~~

默认映射门控关闭，解码状态保持无效并闭锁。CH1～4采用读取到的PX4标定，CH2反向；通道用途见《详细信息表》。CH7、CH8分别由PX4负责解锁与急停。

### 6.2 启动飞控执行器

~~~bash
roslaunch ducted_bringup flight_control.launch
~~~

此入口默认包含RC监视，不要再单独启动一份。如果已有RC节点，可使用 `start_rc_monitor:=false`。

~~~bash
rostopic echo /ducted/control/status
rostopic echo -n 1 /ducted/control/ready
~~~

默认 `enable_flight_output=false`，不会发送飞行目标。启动节点本身不会接管或解锁。
启用输出需要显式设置飞控输出和RC映射参数，并满足持续有效的定位、遥控、FCU状态及数值一致性检查。

PX4 通信接口：外部定位由 `/mavros/odometry/out` 发送；飞行位置和航向目标由 `/mavros/setpoint_position/local` 发送，允许输出时20 Hz。模式切换走 `/mavros/set_mode` 服务，由执行器请求并检查反馈。状态、位置、落地反馈分别查看 `/mavros/state`、`/mavros/local_position/pose`、`/mavros/extended_state`。MAVROS 经 `/dev/ttyTHS0`、921600 波特率，以 MAVLink 2 与 PX4 通信。

### 6.3 控制服务

~~~bash
rosservice type /ducted/control/command
rossrv show ducted_msgs/FlightCommand
~~~

服务请求为 `command` 和 `target`，响应为 `accepted`、`message`。

| command | 行为 |
|---|---|
| `engage` | 捕获当前位置，预发送目标，再按反馈进入OFFBOARD；要求FCU已解锁，软件不代为解锁 |
| `hold` | 保持实际位置，撤销旧目标请求；保持状态仍可能拥有OFFBOARD控制权 |
| `takeoff` | 在已接管状态下，使用新鲜 `odom` 目标的绝对Z；要求ON_GROUND反馈，维持当前XY与航向 |
| `land` | 请求AUTO.LAND并等待实际模式/着陆反馈 |
| `release` | 请求释放OFFBOARD控制权，跟踪模式反馈 |
| `reset` | 清除满足复位条件的锁存闭锁，不自动接管 |
| `abort` | 自动序列使用的中止请求；预发送时撤销接管，已接管且数据有效时保持当前位置，失效时撤销输出；不反向取消 PX4 已接管的降落 |

例如请求保持：

~~~bash
rosservice call /ducted/control/command \
  "command: 'hold'
target:
  header: {frame_id: 'odom'}
  pose:
    position: {x: 0.0, y: 0.0, z: 0.0}
    orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}"
~~~

`hold`不使用示例中的目标位置，而是捕获实际位置。默认关闭输出时服务会拒绝请求；`accepted=true`也只表示接受转换请求，最终行为须查看状态反馈。
`takeoff`目标需要当前时间戳，不能复制固定时间的请求长期使用。

## 7. EGO 局部规划与航点任务

### 7.1 启动 EGO 局部规划

~~~bash
roslaunch ducted_bringup ego_planner.launch
~~~

~~~bash
rostopic echo /ducted/navigation/status
rostopic info /ducted/navigation/preview
rossrv show ducted_navigation/Navigate
~~~

默认输出与几何确认门控均关闭。实际输出依赖新鲜点云、中心AGL、外部定位和已就绪的飞控执行器；仅启动节点不会运动。
机体包络已使用60×70×20 cm的中心长方体。规划器输出绝对位置，地面高度仅用于检查候选位置的离地净空。

| 导航状态 | 含义 |
|---|---|
| `IDLE` | 无活动目标 |
| `CLEAR` | 可沿当前方向推进 |
| `AVOIDING` | 正在选择绕障方向 |
| `BLOCKED` | 当前没有满足碰撞/运动约束的推进目标 |
| `STALE_INPUT` | 数据、就绪条件或快照失效 |
| `GOAL_REACHED` | 规划到点状态，任务仍核对实际位姿和停留 |

`/ducted/navigation/command`支持 `goal`和`cancel`。目标为带新鲜时间戳的 `PoseStamped`，请求必须有唯一ID；取消使用对应活动ID。
EGO 根据实时点云优化局部 B 样条。航点任务保持同一导航接口，在 RViz 中以 odom 查看 `/ducted/ego/local_path`。它不提供跨大范围障碍的全局绕行路线。

规划器只向 `/ducted/control/target`发送通过检查的位置目标，不直接调用MAVROS模式服务。此启动文件默认仍禁止输出；基座、有效定位、地面高度、控制器和原有确认门控均须满足。规划核心服务是只读计算接口，完整导航链路仍执行原有门控。

EGO 无需占据地图文件。默认局部感知半径4 m，局部目标最远2.8 m，并受机体净空、实测高度以及任务/飞控工作范围约束。局部未命中格子不等于经过证明的自由空间；遮挡或局部死胡同可能使任务停止。

`local_avoidance.launch` 也启动 EGO，与 `ego_planner.launch` 二选一。旧全局规划入口已移除。

### 7.2 配置航点文件

模板位置：

~~~

每个航点包含坐标系、绝对位置和偏航角，例如：

waypoints:

    position: [0.0, 0.0, 1.0]
    yaw: 0.0
  - frame_id: map

这是字段示例，不是可直接用于任意场地的航线。完整配置还包括 `mission_id`、`workspace`、容差和超时；保留模板中的完整结构。
`map`目标经完整TF转换到 `odom`，不能只更改坐标系名称。

### 7.3 启动与操作

~~~bash

~~~

默认 `enable_commands=false`。加载任务文件不会自动执行任务、接管、起飞或降落。

## 8. 按需组合启动

基础层始终单独运行。其余模块可组合，例如重定位和数据记录：

~~~bash
roslaunch ducted_bringup modules.launch \
  localization:=relocalization \
  map_file:=/home/nrc/catkin_ws/maps/site_b/GlobalMap.pcd \
  start_recording:=true
~~~

| 参数 | 可用值或作用 |
|---|---|
| `localization` | `none`、`mapping`、`relocalization` |
| `start_external_odometry` | 独立转发；仅在基础层显式禁用转发时使用，日常保持false |
| `start_terrain` | 地面高度 |
| `start_rc_processing` | RC处理 |
| `start_flight` | 飞控执行器，包含RC处理 |
| `start_avoidance` | EGO 局部规划；不需要占据地图文件 |
| `start_mission` | 航点任务 |
| `start_recording` | 数据记录 |

所有 `start_*`默认false。模块组合不会自动打开确认和输出门控。
组合参数中，导航输出名为 `enable_navigation_output`，任务指令名为 `enable_mission_commands`；它们分别转发给子launch的 `enable_output`、`enable_commands`。
外部里程计使用 `/ducted/localization/frames_ready`，建图和重定位均可提供局部机体里程计。建图时还需将地形和 EGO 的 `cloud_topic` 指向 `/ducted/mapping/cloud_registered`，航点采用 `odom` 坐标；使用 `map` 航点需有效的重定位校正。

## 10. 停止顺序

对于数据查看、建图或默认关闭输出的模块：

1. 建图模式先调用保存服务，检查文件后停止建图。
2. 停止任务、避障和飞控等上层模块。
3. 停止地形、适配器和重定位。
4. 停止基础层，记录器可继续保留这段退出过程。
5. 最后停止记录器，等待bag收尾，使用 `rosnode list`核对。

若飞控正在拥有实际控制权，先完成对应的保持、释放或降落状态转换，再结束节点。`Ctrl+C`只是停止进程，不是降落指令；也不要使用轮式机器人的零速度话题代替本系统控制服务。

## 11. 快速排错

| 现象 | 首先检查 |
|---|---|
| 雷达无数据 | eth0的192.168.1.50、雷达192.168.1.109、驱动配置和节点 |
| MAVROS断连 | ttyTHS0、921600、权限、FCU供电与连接 |
| 基础层退出或不就绪 | `/diagnostics`、MAVROS状态、雷达数据年龄 |
| 建图或重定位无输出 | 基础层先启动、Livox点云/IMU、初始化日志 |
| 地图不匹配 | `map_file`、当前场景、RViz初值话题和方向 |
| 适配器无输出 | 确认门控、重定位就绪、初始化FCU姿态、frame和时效 |
| 地面高度无效 | 参考门控、精确时刻TF、中心参考、地面支撑、断流 |
| RC闭锁 | `mapping_confirmed`、原始通道、急停电平、超时 |
| 飞控不接管 | `enable_flight_output`、RC模式、FCU状态、数值一致性、`reason` |
| 任务暂停 | 导航/飞控状态、AGL有效性、请求ID、输入年龄 |
| 地图文件不全 | 保存是否在节点运行时调用、目录是否存在、分辨率是否大于0 |

配套文档：[详细信息表](涵道四旋翼无人机_详细信息表_V1.0.md)、[开发实施文档](涵道四旋翼无人机_开发实施文档_V1.0.md)。


本版按运行阶段划分公共TF（2026-09-12更新）：

- 仅基础系统：无定位TF边，不出现`map`、`odom`、`camera_init`或`body`定位链；`base_link`为机体参考。
- 建图：`odom → camera_init → body → base_link`，不存在`map`。
- 重定位成功且源数据新鲜：`map → odom → camera_init → body → base_link`。

`camera_init → body`由独立的局部FAST-LIO发布。默认 `ducted_localization` 复用该局部点云，以 FPFH/RANSAC 完成未知位姿初始化，随后约 1 Hz 做点到面 ICP 地图跟踪。它把有效全局校正应用到每条新鲜局部里程计，保留完全相同的源时间戳，发布 `/ducted/relocalization/global_odom`（map/body）且不发布 TF。`world_tf_owner.py`按相同扫描时间戳配对全局与局部机体位姿，计算`T_map_odom = T_map_base × inverse(T_odom_base)`；全局校正不会重置局部FAST-LIO。数据过期或重定位无效时停止发布全局校正，`/ducted/localization/map_ready=false`。TF缓存可能短暂保留旧变换，不应只看树中是否还显示map判断定位有效。

`body`是MID360内部IMU参考，不是机体中心；`body → base_link`为原安装外参的逆变换，外参数值未改。保存PCD坐标沿用建图的`camera_init`数值，加载后将该固定地图坐标命名为`map`，建图时无需发布map TF。重定位RViz的Fixed Frame使用`map`；建图使用`odom`或`camera_init`。

MAVROS的ENU/NED、FLU/FRD辅助变换移至`/mavros/internal_tf_static`，其内部里程计转换仍使用这些变换，公共TF树不再出现辅助根。旧`odom → map`链已移除。默认重定位使用一个局部 FAST-LIO 和一个独立配准工作进程；不会同时启动旧 `sfast_lio` 地图匹配。显式 `use_global_relocalizer:=false` 可回退旧后端。

## 自动飞行组合（EGO）

“起飞至离地一米、前飞三米、悬停五秒、约 0.2 m/s 缓降”的分终端操作见[自动飞行任务操作手册](涵道四旋翼无人机_自动飞行任务操作手册_V1.0.md)。该任务准备脚本要求已完成重定位。平地接地准备使用 `python3 prepare_forward_test.py --confirm-ground-contact`；无需先把飞机抬高获得雷达高度。接地参考仅允许限时垂直起飞，前飞仍要求真实有效的 `h_agl`。

入口 `automatic_flight.launch` 组合飞控执行器、EGO、航点任务和自动协调节点。先启动基础层、所需定位及相对高度模块；外部里程计转发已由基础层自动启动。任务组合与独立飞控／导航／航点节点不能重复运行。

默认全部输出关闭。自动流程不调用解锁服务：操作员解锁后，收到明确启动请求才按“预发送与 OFFBOARD 接管 → 垂直起飞 → 航点任务 → 末点悬停或配置降落”执行。默认起飞目标为启动时绝对 odom Z 加 `takeoff_rise`（默认1.1 m）；指定正值 `takeoff_agl` 时，改为根据实测地面或明确确认的起飞接地参考计算离地目标；航点本身仍配置绝对 map/odom 高度，不能把 h_agl 填进绝对 Z。

~~~bash
# 启动组合仅加载节点，默认不产生飞行输出
roslaunch ducted_bringup automatic_flight.launch \
  mission_file:=/home/nrc/catkin_ws/src/ducted_mission/config/mission.yaml
rostopic echo /ducted/automatic/status
~~~

实际执行需显式启用 `enable_commands:=true enable_flight_output:=true enable_navigation_output:=true geometry_confirmed:=true mapping_confirmed:=true`，并满足外部里程计、地形与遥控器自身门控；之后才可调用：

~~~bash
rosservice call /ducted/automatic/start "{}"
rosservice call /ducted/automatic/cancel "{}"
~~~

`finish:=hold` 是默认值；`finish:=land` 仅在航点任务成功且末点保持确认后请求 PX4 `AUTO.LAND`，并等待落地且未解锁反馈。 `finish:=slow_land` 在任务成功后执行约 0.2 m/s 的受控下降，接地确认后交给 PX4 完成降落。不会因启动、重启、数据恢复或前一次完成自行开始新任务。

起飞前和爬升期间检查实时点云、机体竖直通道、倾角及数据新鲜度，按扫描时间匹配位姿历史并覆盖期间运动。RC 切回手动／保持、急停、数据中断、任务失败或取消会撤销自动序列；已进入 PX4 降落的取消不反向切回 OFFBOARD。普通取消捕获当前位置保持；数据或控制权失效时停止外部控制输出，由原飞控失效逻辑处理。

状态话题 `/ducted/automatic/status` 为 JSON 字符串，含 `state`、`reason`、`generation`、`target_z`、`finish`、`healthy`、`health_reason`。`/ducted/automatic/flight_lease` 与 `mission_lease` 提供0.5秒心跳约束，组合中任一授权中断都会被对应执行器检查。服务超时不重试飞行动作，`FAULT` 闭锁阻止再次自动启动。

原 `waypoint_mission.launch` 仍适合已经接管并悬停后的单独航点操作。官方 EGO 来源和修改记录见 `catkin_ws/src/ducted_planning/vendor/ego/PROVENANCE.md`。

本次自动全局重定位、手动初值和持续跟踪的验证结果见[2026-09-12 验证记录](verification/2026-09-12-global-relocalization.md)。
