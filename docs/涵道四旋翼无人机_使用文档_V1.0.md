# 涵道四旋翼无人机使用文档

控制指令采用分步操作：`state=1` 只起飞并悬停，`state=2` 才开始／恢复任务，`state=3` 降落；悬停时收到新目标只加载，不自动执行。

2026-09-15：EGO 源码保留但运行冻结。当前 C++ `ducted_offboard` 将任务状态机和飞控执行器拆为独立模块与 20 Hz 线程，保持一个节点，仅支持直接限速航点跟踪，**没有自动避障**。1 起飞后悬停，2 执行／恢复任务，3 使用 PX4 AUTO.LAND 降落。

> 本文介绍现有系统的连接、检查、建图、保存、重定位、地面高度、遥控读取、直接航点控制和记录操作。
> 文档版本：V1.0；硬件配置核对日期：2026-09-12；软件与文档更新日期：2026-09-15。
> 参数速查见《详细信息表》，源码与编译见《开发实施文档》。

## 1. 连接与检查

### 1.1 登录主控

~~~bash
ssh nrc@192.168.50.140
cd /home/nrc/catkin_ws
~~~

后续命令均在机载主控上执行。当前 `nrc` 用户的新 Bash/SSH 终端已自动加载 ROS 和工作空间，无需重复 source；其他主机或未配置的 shell 才需执行 `source /home/nrc/catkin_ws/devel/setup.bash`。

### 1.2 网络、串口和时间

~~~bash
ip -brief -4 address
ping -c 2 192.168.1.109
ls -l /dev/ttyTHS0
groups
timedatectl show -p NTP -p NTPSynchronized -p Timezone
~~~

| 检查项 | 当前配置 |
|---|---|
| 无线地址 | `192.168.50.140/24` |
| 雷达接收地址 | eth0含 `192.168.1.50/24` |
| 雷达地址 | `192.168.1.109` |

| 串口权限 | `nrc`属于`dialout`，串口可读写 |

### 1.3 确认模块运行情况

~~~bash
rosnode list
~~~

未启动ROS主站时，该命令报无法连接主站是正常现象。若已有节点，先核对其用途，再决定需要启动哪个模块，避免重复运行MAVROS、雷达、建图或重定位。

## 2. 启动基础层

终端A：

~~~bash
roslaunch ducted_bringup base_system.launch
~~~

基础层默认启动MAVROS、MID360驱动、基础健康监视器和等待定位数据的外部里程计转发。它是其他功能的共同前置，不发送飞行目标、模式切换或解锁指令。

终端B检查：

~~~bash
rostopic echo -n 1 /mavros/state
rostopic hz /livox/lidar
rostopic hz /livox/imu
rostopic echo -n 1 /ducted/system/ready
~~~

`rostopic hz`持续显示统计，按 `Ctrl+C` 结束该检查命令。
通过条件为飞控 `connected: true`、雷达数据持续更新、基础层持续发布 `data: true`。雷达点云配置10 Hz，RC实测约20 Hz；IMU以实际测得频率为准。

运行自动检查并保存结果：

~~~bash
mkdir -p /home/nrc/catkin_ws/logs
rosrun ducted_bringup startup_check.py --profile base \
  --output /home/nrc/catkin_ws/logs/startup_base_manual.json
~~~

检查器输出JSON，成功时 `passed=true`。它还检查RC传输、串口权限、MAVROS坐标转换TF和定位发布者是否重复。基础层的 `ready=true` 本身不代表飞控已取得控制权。

## 3. 建图与保存

### 3.1 启动建图

保持基础层运行，另开终端：

~~~bash
roslaunch ducted_bringup mapping.launch
~~~

`mapping.launch`不包含雷达或MAVROS。默认等待基础就绪最多15秒，未就绪时退出。

检查：

~~~bash
rostopic hz /ducted/localization/odom
rostopic hz /ducted/mapping/cloud_registered
rostopic echo -n 1 /ducted/localization/odom/header
rostopic echo -n 1 /ducted/localization/odom/child_frame_id
rosrun tf tf_echo odom base_link
~~~

期望 `header.frame_id=camera_init`、`child_frame_id=body`，点云和里程计持续更新。
需要可视化时运行 `rviz`，Fixed Frame设为 `odom`（或`camera_init`），添加 `/ducted/mapping/cloud_registered` 的PointCloud2和 `/ducted/localization/path` 的Path显示。

`base_system.launch` 已包含外部里程计转发。建图定位就绪后，数据自动送入 PX4，无需再启动 `external_odometry.launch`。
检查 `/ducted/external_odometry/ready` 为 `true`、`/mavros/odometry/out` 持续发布，及 `/mavros/estimator_status` 中水平位置与速度有效。由操作员确认遥控器 kill 状态并尝试切换 Position。建图期间不需要 `map` 坐标系。

### 3.2 采集与坐标理解

采集应覆盖墙面、门框、转角等三维结构，保持雷达安装固定，尽量从不同方向观察相同区域。
建图原始点云的Z属于固定 `camera_init` 坐标；原始轴可能倾斜，不直接将其Z当作竖直离地高度。

### 3.3 显式保存地图

在建图节点仍运行时，执行工作空间根目录的脚本。脚本自动加载 ROS 环境、按时间生成尚不存在的地图目录，并显示后台保存进度。

基础系统与建图仍需保持运行，机体保持静止；后台化不意味着可以停止建图。

~~~bash
cd /home/nrc/catkin_ws
./save_map.sh
~~~

地图保存在 `maps/map_时间戳/GlobalMap.pcd`。需要指定名称时使用 `./save_map.sh site_b`，保存到 `maps/site_b/`；已有目录会拒绝覆盖，不要提前创建目标目录。默认保留0.05 m（5 cm）静态点云细节，不再额外降采样到20 cm。

Ctrl+C 只退出进度显示，后台保存继续。查询最新保存任务或重新显示进度：

~~~bash
./save_map.sh --status
./save_map.sh --wait
~~~

`SUBMITTED`表示已提交，`SAVING`表示处理中；建图节点提供`completed/total`扫描进度与`FILTERING/WRITING`阶段。只有`SUCCEEDED`表示服务成功且清单要求的文件齐全：默认六个文件，启用观测占据导出时七个。`FAILED`查看建图终端和任务目录中的`worker.log`；`UNKNOWN`表示连接中断等原因使结果无法确认，应检查目标目录与服务端后再决定是否重试。程序不会自动重试。

原 Python 客户端继续支持自定义分辨率和完整路径：`rosrun ducted_bringup save_map.py start --destination /完整/新目录 --resolution 0.1`可显式输出10 cm地图；默认`--resolution 0`保留原生5 cm细节，更小的请求值不会凭空增加细节。程序打印的Job目录保存状态和日志；查询历史任务可加`--job /完整/Job/目录`。同一ROS主站拒绝重叠的后台保存请求，不要同时手动调用旧保存服务。

传统同步`rosservice call /ducted/mapping/save_map`接口继续保留。后台客户端同样调用这个服务，过滤期间建图更新仍会暂停。导出时并行读取和半径去噪，随后按原时间顺序执行动态过滤；静态确认的8帧、2秒条件保留。

等待状态为`SUCCEEDED`，然后检查：

~~~bash
find /home/nrc/catkin_ws/maps/site_b -maxdepth 1 -type f \
  -printf '%f %s bytes\n' | sort
~~~

默认应生成：

~~~text
trajectory.pcd
transformations.pcd
SurfMap.pcd
filterGlobalMap.pcd
GlobalMap.pcd
mapping_metadata.yaml
~~~

EGO和重定位不依赖`observed_occupancy.pcd`，因此默认省去该文件和对应的射线遍历。需要它时，在本次采集开始前运行`roslaunch ducted_bringup mapping.launch export_occupancy:=true`；此时保存仍额外生成占据文件，处理会更慢。`mapping_metadata.yaml`记录是否导出占据栅格、实际分辨率、点数和处理时间。

确认文件已写入后，才在建图终端按 `Ctrl+C`。当前配置不在退出时自动保存，也不需要轮式系统的 `finalize_map.py`。
默认动态过滤模式下，成功标志要求整套文件完成写入。已有目录会被拒绝，不能覆盖旧地图。保存可能需要重放多帧扫描，调用期间应保持机体静止，等待结果后再退出。

动态过滤需要同一体素至少8帧命中、累计观测跨度至少2秒；移动后离开的物体还需要后续射线穿过其原位置才能清除。过滤只作用于保存的静态地图，在线定位仍接收完整点云，当前自动避障已冻结；它不保证移除静止很久的人或完全被遮挡的物体。原地图关键帧与扫描同步按回环优化位姿重放。扫描档案位于 `logs/mapping-scans-*`，每次建图默认上限2 GiB；空间或帧数超限时保存会报错，避免输出缺帧地图。

## 4. 加载地图与重定位

### 4.1 启动

飞机落地锁定后，停止控制器和建图，保持基础层运行。选择与当前场地对应的地图，以下只将 `flight_test_01` 作为默认示例，可修改第一行路径：

~~~bash
MAP_FILE="/home/nrc/catkin_ws/maps/flight_test_01/GlobalMap.pcd"
ls -lh "$MAP_FILE"
roslaunch ducted_bringup relocalization.launch map_file:="$MAP_FILE"
~~~

重新选择地图时修改 `MAP_FILE`，并将其传入 `map_file`。也可使用 `./save_map.sh <新名称>` 保存的地图；没有已有地图时直接使用建图定位。飞行期间不切换定位入口或地图。

地图必须与当前场景对应。省略 `map_file` 会读取 `/home/nrc/catkin_ws/maps/GlobalMap.pcd`，不会自动寻找最新地图。

### 4.2 自动搜索与手动初始位姿

默认自动搜索未知位置和姿态，无需先点击 RViz。保持飞机未解锁、基础层和雷达数据正常；程序累计多帧点云，通过 FPFH/RANSAC 全局匹配、点到面 ICP 精配准，并要求两次独立结果一致。初始化默认限时 60 s。成功后终端打印 `success=true`、`pose=(x,y,z)`、姿态四元数、`fitness` 和 `rmse`，坐标为 `map` 下的机体中心 `base_link`。

成功后保持本终端运行：FAST-LIO 持续输出局部里程计，全局节点约每秒做一次 ICP 地图跟踪，既有 TF 节点持续维护 `map → odom`。初始化成功不代表 launch 已执行结束。

自动失败或需要指定起点时，仍可使用下面的 RViz 操作；有效手动初值会中断当前自动搜索，优先执行手动初始化。仅允许在未解锁且数据新鲜时重新初始化。

运行 `rviz`，Fixed Frame设为 `map`。
在Tool Properties中，把 **2D Pose Estimate** 的Topic改成 `/ducted/relocalization/initialpose`，再指定地图中的位置和机头方向。
同时显示 `/ducted/relocalization/global_map` 和 `/ducted/relocalization/registered_scan`，观察当前点云与地图是否重合。

2D工具主要给出平面位置和朝向，默认 Z 为 0；这里的初值表示机体中心，不是雷达原点，节点会补偿原有安装外参。高度差较大或地图坐标倾斜时，使用带正确 Z/姿态和当前时间戳的 `geometry_msgs/PoseWithCovarianceStamped`，坐标系设为 `map`。

只使用手动初始化时，在启动命令末尾增加 `auto_initialize:=false`。需要重新自动搜索时，在未解锁状态执行：

~~~bash
rosservice call /ducted/relocalization/retry "{}"
~~~

该服务的 `success: true` 表示请求已受理；最终匹配结果查看状态话题。点云/里程计过期、跟踪校正过期或连续跟踪失败会撤销定位有效性，不会悄悄重新搜索。

### 4.3 检查重定位

~~~bash
rostopic echo -n 1 /ducted/relocalization/ready
rostopic echo /ducted/relocalization/status
rostopic echo /ducted/localization/map_ready
rostopic echo -n 1 /ducted/relocalization/registered_scan/header
rostopic hz /ducted/localization/odom
rosrun ducted_bringup startup_check.py --profile localization \
  --output /home/nrc/catkin_ws/logs/startup_localization_manual.json
~~~

`/ducted/relocalization/status` 包含 `state/source/success/reason/position/quaternion_xyzw/fitness/rmse`；有效状态为 `TRACKING`，来源为 `AUTO` 或 `MANUAL`。`/ducted/relocalization/ready` 与 `/ducted/localization/map_ready` 必须有效且持续更新；仅有局部里程计消息不等于地图匹配已成功。
启动检查的localization档验证源里程计和基础依赖，重定位质量仍须查看就绪话题和匹配日志。

## 5. 外部里程计与相对地面高度

### 5.1 数据链路

~~~text
FAST-LIO /Odometry
  → launch重映射为 /ducted/localization/odom
  → fastlio_odometry_adapter.py（随建图/重定位启动，发布完整TF）
  → /ducted/localization/body_odom
  → external_odometry_relay.py（随基础层启动，等待有效定位后发送）
  → /mavros/odometry/out
  → MAVROS ENU/FLU 到 NED/FRD 转换
  → PX4 MAVLink ODOMETRY
~~~

`/mavros/odometry/out`是本系统从ROS向PX4送入外部里程计的入口。
适配器随建图或重定位自动启动，需要基础层就绪和有效定位数据；重定位初始化成功仅决定全局`map → odom`校正是否可用，局部链可独立工作。坐标对齐需要新鲜的未解锁飞控姿态。它补偿传感器安装关系，并建立 `odom → camera_init → body → base_link` 主链。

### 5.2 随基础层自动启动

基础层末尾包含 `external_odometry.launch` 并设置 `input_contract_confirmed=true`。仅启动基础层时，转发节点等待定位；启动建图或重定位、局部定位链有效后，自动向 `/mavros/odometry/out` 发送。节点启动顺序由就绪门控协调，不依赖 launch 文件中的书写顺序。

~~~bash
rostopic echo -n 1 /ducted/external_odometry/ready
rostopic hz /mavros/odometry/out
~~~

输出应为 `header.frame_id=odom`、`child_frame_id=base_link`。不要再单独启动同名转发节点。

若只想查看转换结果而不送给 PX4，在启动基础层时禁用自动转发，再另开终端启动预览：

~~~bash
roslaunch ducted_bringup base_system.launch start_external_odometry:=false
~~~

保持基础层及建图/重定位运行，在另一个终端执行：

~~~bash
roslaunch ducted_bringup external_odometry.launch \
  input_contract_confirmed:=true \
  output_odom:=/ducted/external_odometry/preview
~~~

独立 `external_odometry.launch` 的确认参数默认仍为 `false`；日常使用由基础层传入 `true`。安装补偿和 TF 适配器仍由建图或重定位负责，转发节点不创建定位 TF。

### 5.3 启动地面高度

保持重定位及有效适配TF运行：

~~~bash
roslaunch ducted_bringup terrain_height.launch
~~~

默认 `reference_confirmed=false`，高度消息会保持无效。参考配置采用机体中心；显式确认该配置的运行方式为：

~~~bash
roslaunch ducted_bringup terrain_height.launch reference_confirmed:=true
~~~

以上是同一模块的两种启动方式，选择其一。

~~~bash
rostopic echo /ducted/terrain/height
rostopic echo -n 1 /ducted/terrain/ready
rosrun ducted_bringup startup_check.py --profile terrain \
  --output /home/nrc/catkin_ws/logs/startup_terrain_manual.json
~~~

| 字段 | 解释 |
|---|---|
| `header.frame_id` | `odom`，竖直对齐后的固定坐标 |
| `ground_z` | 拟合地面在该坐标系中的高度 |
| `agl` | 默认机体中心到地面的竖直距离 |
| `variance` | 高度估计方差 |
| `valid` | 当前估计是否可用；false时不能使用保留数值 |
| `reason` | 无效原因；接地参考不会改变本话题的有效性 |

机体总高20 cm、原点居中。水平姿态下机底离地高度为 `agl - 0.10 m`。
当前避障接口要求 `base_link`中心AGL；不要仅把地形模块改为 `body_bottom` 后仍接入原避障配置。
点云断流、位姿超时、TF缺失、地面支撑不足或台阶多层歧义都会使高度无效。

## 6. 遥控器读取

### 6.1 查看遥控器

基础层已经提供原始RC数据：

~~~bash
rostopic echo -n 1 /mavros/rc/in
rostopic hz /mavros/rc/in
~~~

需要解码状态时：

~~~bash
roslaunch ducted_bringup rc_processing.launch
~~~

~~~bash
rostopic echo /ducted/rc/state
~~~

默认映射门控关闭，解码状态保持无效并闭锁。CH1～4采用读取到的PX4标定，CH2反向；通道用途见《详细信息表》。CH7、CH8分别由PX4负责解锁与急停。

### 6.2 新 C++ 飞控执行器

本节的 RC 节点只读取遥控数据。自动起飞、位置目标执行和降落由独立的 C++ `ducted_offboard` 提供，见自动飞行任务操作手册。

## 7. 自动控制与冻结的规划模块

EGO 源码保留，`ego_offboard.launch`、`ego_planner.launch`、`local_avoidance.launch` 和直接规划节点入口均报告“EGO 已冻结”并退出。当前不能通过参数临时重新启用，`execution_mode=ego` 也会被控制器拒绝。

自动任务使用 `roslaunch ducted_offboard offboard_control.launch`。控制器内部任务层只处理指令、航点、坐标和到点判据，执行器独立发送 20 Hz MAVROS 位置目标及执行服务请求。任务心跳超过 0.5 s 时撤销推进，定位有效且仍在 OFFBOARD 时悬停，线程恢复后不会自动续飞。

当前是限速位置/yaw 直接跟踪，没有自动避障，不要求地面高度模块或 EGO 点云许可。完整七步命令见[自动飞行任务操作手册](涵道四旋翼无人机_自动飞行任务操作手册_V1.0.md)，重定位使用 `flight_test_01/GlobalMap.pcd`，也可选择建图定位。

## 8. 按需组合启动

基础层始终单独运行。其余模块可组合，例如重定位和数据记录：

~~~bash
roslaunch ducted_bringup modules.launch \
  localization:=relocalization \
  map_file:=/home/nrc/catkin_ws/maps/flight_test_01/GlobalMap.pcd \
  start_recording:=true
~~~

| 参数 | 可用值或作用 |
|---|---|
| `localization` | `none`、`mapping`、`relocalization` |
| `start_external_odometry` | 独立转发；仅在基础层显式禁用转发时使用，日常保持false |
| `start_terrain` | 地面高度 |
| `start_rc_processing` | RC处理 |
| `start_avoidance` | 已冻结；设为 true 会拒绝运行组合，不启动规划或控制节点 |
| `start_recording` | 数据记录 |

所有 `start_*`默认false。模块组合不会自动打开确认和输出门控。
外部里程计使用 `/ducted/localization/frames_ready`，建图和重定位均可提供局部机体里程计。建图时独立地形模块的 `cloud_topic` 应指向 `/ducted/mapping/cloud_registered`。直接控制器不订阅点云。新的航点由 `ducted_offboard` 管理，组合中的 `start_avoidance` 必须保持 false。

## 9. 日志和数据记录

基础层就绪后启动：

~~~bash
roslaunch ducted_bringup recording.launch
~~~

记录器收到两次近期有效基础心跳后，在 `logs/recordings`下创建UTC时间加UUID目录。
会话包含选定话题的bag、参数快照和退出信息。运行后基础层丢失时继续记录，以保留故障前后数据。

需要完整参数副本时，在业务节点全部加载后另外执行：

~~~bash
rosparam dump /home/nrc/catkin_ws/logs/runtime_params.yaml
~~~

此命令写入独立参数文件；记录器自身的 `session.json`仅包含选定命名空间的快照。

停止记录终端，等待写入索引和正常退出，再检查对应文件：

~~~bash
find /home/nrc/catkin_ws/logs/recordings -maxdepth 2 -type f \
  -printf '%p %s bytes\n'
~~~

对所选会话中的实际bag执行 `rosbag info /实际路径/telemetry_0.bag`。`.active`仍存在时不应把会话视为已经正常收尾。

## 10. 停止顺序

对于数据查看、建图或默认关闭输出的模块：

1. 建图模式先调用保存服务，检查文件后停止建图。
2. 飞行测试须先落地锁定，再停止控制器；仅数据查看时停止对应上层模块。
3. 停止地形、适配器和重定位。
4. 停止基础层，记录器可继续保留这段退出过程。
5. 最后停止记录器，等待bag收尾，使用 `rosnode list`核对。

本版按运行阶段划分公共TF（2026-09-12更新）：

- 仅基础系统：无定位TF边，不出现`map`、`odom`、`camera_init`或`body`定位链；`base_link`为机体参考。
- 建图：`odom → camera_init → body → base_link`，不存在`map`。
- 重定位成功且源数据新鲜：`map → odom → camera_init → body → base_link`。

`camera_init → body`由独立的局部FAST-LIO发布。默认 `ducted_localization` 复用该局部点云，以 FPFH/RANSAC 完成未知位姿初始化，随后约 1 Hz 做点到面 ICP 地图跟踪。它把有效全局校正应用到每条新鲜局部里程计，保留完全相同的源时间戳，发布 `/ducted/relocalization/global_odom`（map/body）且不发布 TF。`world_tf_owner.py`按相同扫描时间戳配对全局与局部机体位姿，计算`T_map_odom = T_map_base × inverse(T_odom_base)`；全局校正不会重置局部FAST-LIO。数据过期或重定位无效时停止发布全局校正，`/ducted/localization/map_ready=false`。TF缓存可能短暂保留旧变换，不应只看树中是否还显示map判断定位有效。

`body`是MID360内部IMU参考，不是机体中心；`body → base_link`为原安装外参的逆变换，外参数值未改。保存PCD坐标沿用建图的`camera_init`数值，加载后将该固定地图坐标命名为`map`，建图时无需发布map TF。重定位RViz的Fixed Frame使用`map`；建图使用`odom`或`camera_init`。

MAVROS的ENU/NED、FLU/FRD辅助变换移至`/mavros/internal_tf_static`，其内部里程计转换仍使用这些变换，公共TF树不再出现辅助根。旧`odom → map`链已移除。默认重定位使用一个局部 FAST-LIO 和一个独立配准工作进程；不会同时启动旧 `sfast_lio` 地图匹配。显式 `use_global_relocalizer:=false` 可回退旧后端。
